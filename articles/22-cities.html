The Cities API lets your software look up a store's cities and their post codes. You can filter the cities by country, state, post code or part of the city name, sort them, and check whether the list changed. Each city has an id, a name, a post_code, the state it is in and the country it is in. You can only read cities. Both endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get the cities of one state List cities with the state's code and the country, such as country=AU&state=VIC, or with the state's id as state, such as state=72. It returns the cities under cities, each with its state and country, and a pagination object
Find the cities that have a post code List cities with post_code, such as post_code=3000. It returns only the cities with exactly that post code. Part of a post code, such as 300, returns no cities
Find a city by part of its name List cities with search, such as search=melb. It returns the cities whose name contains that text, in any letter case. It does not match post codes. Filters you send together must all match
Sort the cities by name or post code List cities with sort=name or sort=post_code, and order=desc to reverse the order. Without sort, cities are sorted by state, then post code, then city name, in ascending order
Get every city, page by page List cities returns 100 cities per call, or the limit you send, from 1 to 100. Send a higher offset while pagination.has_next is true. pagination.total is the number of cities that match your filters across all pages
Find out whether the cities list changed without downloading it Check the cities list returns 200 with headers only. Its ETag is the same one List cities returns when you send no query parameters. Compare it with the ETag you saved

All endpoints

These two endpoints list the store's cities and return the list's headers, both at the path /api/v4/app/cities.

EndpointMethodPath
List cities
Returns up to 100 cities per call, sorted by state, post code and name.		GET…/cities
Check the cities list
Returns the headers of the cities list, including its ETag, with no body.		HEAD…/cities

Good to know

Send country with a state code. Codes such as WA repeat across countries, so state=VIC on its own is rejected with 400 and the detail code country_required. Send country=AU&state=VIC, or send the state's id as state, such as state=72, which works without country. A state name such as Victoria matches no cities.

Take the country and state values from the Countries API. A city's country.id is the country's id from List countries, and its state.id is the state's id from List the states of a country. Send the country's id or its two-letter code in any letter case, such as 12, AU or au, as country. A country name such as Australia is rejected with 400.

You can only read cities. POST, PUT, PATCH and DELETE on /api/v4/app/cities are rejected with 405. There is no path for a single city: no endpoint takes the city's id as a path parameter, and GET /api/v4/app/cities/{city_id} returns 404 with the error code not_found. To find one city, filter List cities instead.

  • The cities list has a read limit. You can make 20 calls within about 10 seconds, with List cities and Check the cities list counted together. The next call is rejected with 429 and the error code rate_limited. The Retry-After header says how many seconds to wait.
  • Every read returns an ETag. Each GET and HEAD response has an ETag and Cache-Control: private, max-age=3600. Send that ETag in If-None-Match, and while it is still current you get 304 with no body. The SDK functions take no headers, so they never send If-None-Match: you get 304 only from your own HTTP calls.
  • Older parameter names still work, but send each parameter once. max is the same as limit, countryId as country, stateId as state, postCode as post_code, and searchText and name as search. A parameter sent twice, or sent together with its other name, is rejected with 400 and the detail code duplicate_parameter.
  • Unknown parameters are ignored. q, dir, page, field_metadata and any other name the listing does not know return 200 and the same cities as without them. Use search, order and offset instead.
  • state.default follows the store's default state. A state has default set to true while it is the default_state in the administration section of the site settings, which you read with Get a settings section. The store's default country does not filter the listing.
