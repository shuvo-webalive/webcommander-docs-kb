The Shipping API lets your software work with a store's shipping methods and shipping classes: list and count them, create, rename and delete them, change a class's description, and choose which method and which class is the default. The only field you set on a shipping method is its name. On a shipping class, you set a name and a description. All eighteen endpoints are available in all seven WebCommander SDKs.

All endpoints

Shipping methods

These endpoints list, count, create, rename and delete shipping methods, and choose which one is the default. The Shipping methods overview lists what each one does.

EndpointMethodPath
List shipping methods
Returns up to 20 shipping methods per call, in id order, with paging details.		GET…/shipping_methods
Check the shipping methods list
Checks that the shipping methods list is reachable. Returns headers only, with no body.		HEAD…/shipping_methods
Count shipping methods
Returns the number of shipping methods in the store.		GET…/shipping_methods/count
Create a shipping method
Creates a shipping method from a name and returns it with its id, which the other calls take as shipping_method_id.		POST…/shipping_methods
Retrieve a shipping method
Returns the shipping method whose id you pass as shipping_method_id.		GET…/shipping_methods/{shipping_method_id}
Check a shipping method
Returns headers only, and 200 even when no method has that shipping_method_id.		HEAD…/shipping_methods/{shipping_method_id}
Rename a shipping method
Changes a shipping method's name and returns the updated method.		PUT…/shipping_methods/{shipping_method_id}
Delete a shipping method
Deletes a shipping method permanently. You cannot delete the default method.		DELETE…/shipping_methods/{shipping_method_id}
Set the default shipping method
Makes a shipping method the default and removes the flag from the previous one.		PUT…/shipping_methods/{shipping_method_id}/default

Shipping classes

These endpoints list, count, create, update and delete shipping classes, and choose which one is the default. The Shipping classes overview lists what each one does.

EndpointMethodPath
List shipping classes
Returns up to 20 shipping classes per call, with classes you create listed first.		GET…/shipping_classes
Check the shipping classes list
Checks that the shipping classes list is reachable. Returns headers only, with no body.		HEAD…/shipping_classes
Count shipping classes
Returns the number of shipping classes in the store.		GET…/shipping_classes/count
Create a shipping class
Creates a shipping class and returns it with its id, which other calls take as shipping_class_id.		POST…/shipping_classes
Retrieve a shipping class
Returns the shipping class whose id you pass as shipping_class_id.		GET…/shipping_classes/{shipping_class_id}
Check a shipping class
Returns 200 and headers only, even when no class has the shipping_class_id you pass.		HEAD…/shipping_classes/{shipping_class_id}
Update a shipping class
Replaces a shipping class's name and description and returns the updated class.		PUT…/shipping_classes/{shipping_class_id}
Delete a shipping class
Deletes a shipping class permanently. You cannot delete the default class.		DELETE…/shipping_classes/{shipping_class_id}
Set the default shipping class
Makes a shipping class the default and sets is_default to false on the previous default.		PUT…/shipping_classes/{shipping_class_id}/default

Good to know

Send the description every time you update a shipping class. Updating a shipping class replaces both its name and its description. If you send only name, the store sets the class's description to null. To keep the description, send it again in the same call: {"shipping_class": {"name": "Bulky Goods", "description": "Items over 20kg"}}.

Checking a method or class does not tell you whether it exists. Check a shipping method returns 200 even when no method has the shipping_method_id you send. Check a shipping class returns 200 even when no class has the shipping_class_id you send. To find out whether it exists, use Retrieve a shipping method with the method's id as shipping_method_id, or Retrieve a shipping class with the class's id as shipping_class_id. Each returns 404 when no method or class has that id. If Retrieve a shipping class returns 404, send it once more before you decide the class is missing. Right after a 404 for a shipping_class_id that no class has, the next Retrieve a shipping class call on the same client returns 404 even for a class that exists.

You cannot delete the default method or class. Only one shipping method is the default, and only one shipping class. Set the default shipping method and Set the default shipping class are the only calls that change it. Each makes the method or class you pass the default, and takes the default from the one that had it. To delete the default, make another one the default first, or the delete is rejected with 409.

  • Send the fields inside shipping_method or shipping_class. A create or update that sends the fields on their own, or inside the plural shipping_methods or shipping_classes, is rejected with 400.
  • Names must be unique. A method's name can be up to 100 characters. A class's name can be up to 50 characters and its description up to 100. A method name that another method already has, or a class name that another class already has, is rejected with 409.
  • Lists return up to 20 methods or classes at a time, even if you send a larger limit. To get more, send the next page number or a higher offset while pagination.has_next is true. Classes you create are listed ahead of the ones already there, newest first, so the default class can be past the first page. Any parameter other than limit, offset, page and field_metadata is rejected with 400.
  • A PATCH request changes nothing. It returns 200 with "isSuccess": false and leaves the method or class as it was. Use Rename a shipping method or Update a shipping class instead.
