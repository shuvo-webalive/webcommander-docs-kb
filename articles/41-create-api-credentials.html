To call the WebCommander API with the new sign-in, your integration needs a client ID and a client secret. Both belong to an API application, which you create in your store's WebCommander admin. You reach the admin by signing in to Hykmah. This article walks through each screen; the numbers on each screenshot match the numbered actions in that step.

See Create API credentials in the developer documentation

Before you start

  • A Hykmah account with access to the company that owns the store.
  • Permission to change the store's settings in the WebCommander admin.

Step 1: Sign in to Hykmah

Go to manage-hykmah.exsited.com. Enter your email address (1) and click Continue (2).

Step 2: Enter your password

Enter your password (1) and click Continue (2). You can also sign in with Google, LinkedIn or GitHub if your account is linked to one of them.

Step 3: Select your company

Under Select company, click the company that owns the store (1). Use the search box if you have access to many companies.

Step 4: Open the WebCommander admin

On the company dashboard, click WebCommander (1) in the top bar, next to the notifications bell. The WebCommander admin opens in a new browser tab.

Step 5: Open Settings

In the WebCommander admin, click Settings (1) at the bottom of the left sidebar.

Step 6: Open API Applications

Under General, click API Applications (1).

Step 7: Start a new application

Click + Create application (1). The list shows the store's existing applications; it is empty until you create the first one.

Step 8: Fill in the application

Complete the form and click Create application (7).

#FieldWhat to enter
1NameAn internal name of 2 to 255 characters, such as erp-sync.
2Display nameThe name shown in the admin, such as ERP sync.
3DescriptionOptional. What the integration does, so others can recognise it later.
4API versionChoose v4, the version the SDKs and the documentation use.
5Redirect URIRequired by the form. The new sign-in does not send it, but the legacy token request must send exactly this value.
6Allow client credentialsTurn it on. Without it, the application cannot get an access token from its client ID and client secret.
7Create applicationSaves the application.

Leave Enabled on: a disabled application cannot get or use tokens. Enforce scopes is on by default; while it is on, the application can call only the endpoints its scopes allow.

Step 9: Copy the client ID and client secret

Hykmah issues the application's credentials. Copy the client ID and the client secret and store the secret in an environment variable or a secrets manager.

Important: secret rotation is not available. If the client secret is exposed, disable the application and create a new one.

Use the credentials

Give the SDK your store's base URL, the auth base URL https://manage-hykmah-api.exsited.com, the client ID and the client secret. The SDK gets the access token, caches it and renews it for you. Authentication (New) shows the setup for every SDK.
