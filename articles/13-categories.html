The Categories API lets your software work with a store's product categories. You can list, count, create, retrieve, replace, update and delete categories, and check whether a category name is taken. You can also read or update one section of a category at a time, such as its tax and shipping settings or the products assigned to it. All ten endpoints are available in all seven WebCommander SDKs.

All endpoints

These ten endpoints list, count, create, retrieve, replace, update and delete the store's product categories, check whether a category name is taken, and read or update one section of a category at a time, at paths that start with /api/v4/admin/categories.

EndpointMethodPath
List categories
Returns up to 20 categories per call, from every tree level, most recently updated first.		GET…/categories
Count categories
Returns how many categories are outside the trash, narrowed by any filters you send.		GET…/categories/count
Check a category name
Returns available: false when any category, even one in the trash, has the name.		GET…/categories/check-name
Create a category
Creates a category and returns it with its id, which other calls take as category_id.		POST…/categories
Retrieve a category
Returns the category whose id you pass as category_id, with all six sections.		GET…/categories/{category_id}
Replace a category
Replaces a category: most fields you leave out reset, but name, sku, url and images stay.		PUT…/categories/{category_id}
Update a category
Changes only the fields you send, in any number of sections, and returns the category.		PATCH…/categories/{category_id}
Delete a category
Moves a category to the trash. You can still retrieve it, but it leaves the listing.		DELETE…/categories/{category_id}
Retrieve a category section
Returns one section of a category, inside category, such as its tax_shipping settings.		GET…/categories/{category_id}/{section}
Update a category section
Changes only the fields you send in one section and returns the whole section.		PATCH…/categories/{category_id}/{section}

Good to know

After a 404, the next request that sends the same JSESSIONID cookie gets that 404 back instead of its own result. A read of a category that exists then returns 404. A delete returns the earlier 404 and its message, such as Category already in trash, and does not delete the category whose category_id you sent. Send the request that follows a 404 without that cookie. After the listing rejects a sort value with 400, the next listing request sent with the same cookie can return that 400 again.

PUT resets most fields you leave out, and PATCH keeps them. Replace a category sets the fields you leave out back to the values of a new category. Only name, sku, url, both images and the tax_shipping fields tax_exempt, tax_message, show_price_with_tax, prices_entered_with_tax and base_price_rounding keep their values when you leave them out. A PUT without general.parent_category moves a child category to the top level. A PUT without assign_products removes all the category's products. A PUT without tax_shipping.tax_profile or tax_shipping.shipping_profile sets that profile to null, even when it sends other tax_shipping fields. Clearing the shipping profile also sets enable_shipping to false. A PUT with a new name leaves the url as it was. Update a category and Update a category section change only the fields you send. The exception is assign_products.products: the list you send replaces the category's products.

A category has six sections, and every write wraps them in category. The sections are general, description, images_media, availability_visibility, tax_shipping and assign_products, as in {"category": {"general": {"name": "Seasonal Produce"}}}. A create, replace or update without category around the sections is rejected with 400 and the message category is required. Retrieve a category section and Update a category section read or write one section at a time, and the section update takes the same wrapper, as in {"category": {"assign_products": {"products": [101, 102, 103]}}}. Without the wrapper, the section update is rejected with 400 and the message <section> is required, such as assign_products is required. A key that a section does not have is rejected with 400, with details[0].code set to unknown_field. So is an unknown key beside the sections, except in a section update, which ignores everything but its own section. A key beside category is ignored.

  • Deleting moves a category to the trash. The category leaves the listing and the count, but Retrieve a category still returns it with in_trash set to true, and Check a category name still reports its name as taken. Deleting it again returns 404 with the message Category already in trash. Its child categories stay in the listing, with parent_category still naming it and parent_in_trash still false. To find out whether a parent category is in the trash, retrieve it with the parent category's id as category_id and read its in_trash. No call restores a category from the trash or deletes it permanently.
  • A create rejects only a name that a top-level category has. Create a category rejects that name in any letter case, even when the top-level category is in the trash, and whatever parent you give the new category. It returns 409 with the message Category name already exists. A name that only child categories have is accepted at any level, even under the same parent, and the new category's url gets a suffix such as -1 or -2. Check a category name returns "available": false for a name that any category has, anywhere in the tree or in the trash. So Create a category can accept a name that Check a category name reports as taken.
  • A listing returns at most 20 categories per call, from every level of the tree. A larger limit is capped at 20. To get the next categories, send a higher offset while pagination.has_next is true. Send parent with the parent category's id to list only its children. A parent that is not a number, such as parent=abc, returns 500. Without sort, the most recently updated categories come first. dir defaults to desc, so sort=name alone sorts Z to A. Send dir as asc to sort A to Z. The listing ignores query parameters it does not know instead of rejecting them, so a misspelled filter filters nothing.
  • Point to another record by its id, send images as a file name and base64 data, and send booleans as true or false. parent_category, layout, tax_profile and shipping_profile take {"id": ...} with the id of the parent category, layout, tax profile or shipping profile. Responses return them as {"id": ..., "name": ...}. selected_customers takes the id of each customer in customers and of each group in groups. A customer or group id that does not exist is dropped without an error. assign_products.products takes the id of each product. Send an image in images_media.image or images_media.background_image as {"filename": "banner.png", "base64": "..."}. A data: URI string returns 500, and no call removes a stored image. A string such as "false", or null, sent for a boolean returns 200 and leaves the stored value unchanged.
