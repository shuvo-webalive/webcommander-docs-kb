A new WebCommander store starts empty. Reading data through the API works straight away, but some writes fail until the store is set up: orders that ship, invoice emails, stock figures and customer logins each need one setting first. This article lists each one, what you get without it, and the call that fixes it.

Set up shipping

A new store has no shipping profile. Until it has a default shipping profile that covers the order's address, every order with delivery_type shipping or delivery is refused with 400 and the message "We do not ship to your location. Please choose a different shipping address." This applies to Create an order, Create an order with a payment and Create an order from a cart. Orders with store_pickup or others_shipping need no profile.

  1. Check. Call Get shipping settings. If default_shipping_profile is null, the store cannot ship yet.
  2. Find the zone. Call List tax zones. A new store already has a zone for each country, such as BUILT_IN_AU for Australia. Note its id.
  3. Create a profile. Create a shipping profile with the wizard creates the profile, a rule for the zone and its rate in one call, for example a flat $10 rate for zone 1. Note the new profile's id.
  4. Make it the default. Creating the profile is not enough. Send {"shipping_settings": {"default_shipping_profile": 1}} to Update shipping settings. Shipping and delivery orders, and orders created from a cart, now go through.

Choose an email provider

A new store's email provider is DEFAULT, which does not count as a provider for invoices. Send an order's invoice answers 409 with "No email provider is configured for this store".

  1. Check. Call Get a settings section with the section email_settings and read service_provider.
  2. Choose SMTP or SendGrid. Send service_provider with the provider's settings to Update a settings section. For SMTP, smtp.encryption takes no, ssl or starttls: a new store can read back TLS, but sending TLS is refused. Gmail and Office 365 connect through the WebCommander admin.
  3. If the invoice still fails. 502 with "The invoice email could not be delivered" means the provider is chosen but the email did not go out. Check the provider's credentials and the order's billing email address.

Turn on stock tracking

A new product does not track its stock: it reads available_stock: 0, a new figure is refused with 409 and the reason tracking_disabled, and orders do not lower it. Send {"tracking": {"enabled": true, "available_stock": 25}} to Change a product's stock to turn tracking on and set the figure in one call. When an order lowers stock is a store setting: read update_stock in the product_inventory section of the ecommerce settings.

Create active customers

Create a customer without status makes the customer awaiting_verification. Such a customer cannot sign in, and Change a password answers 401 "Invalid Current Credential". Send "status": "active" when you create the customer, or set it later with Update a customer.

Good to know

  • Use order_id and customer_id everywhere. Paths, filters and request fields take these ids. Responses also return an internal_id: keep it for reference, but do not send it. On a new store the first order and the first customer often have the same number for both, so a mix-up only shows from the second record on.
  • Deleting a customer moves it to the trash. The customer leaves List customers, but Retrieve a customer still returns it, with is_in_trash: true.
  • Only some orders can be deleted. Delete an order works on a cancelled order that was never paid, refunded or shipped. Any other order is refused with 409; cancel orders you no longer need instead.
