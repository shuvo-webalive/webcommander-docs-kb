The WebCommander SDKs are installed from their source repositories rather than from a package registry such as PyPI, npm or NuGet. This article explains what you need and how installation works. The developer documentation has the exact commands for each language.

See the installation guide

Before you start

You need read access to the SDK repositories on Bitbucket. If you do not have it, ask your WebCommander contact.

How installation works

1Clone the SDK's repository. Use the development branch; it is the main branch.

2Run one command in the clone to make it ready, for example npm install for JavaScript.

3Point your project at the clone. Keep the clone next to your project, because the paths are relative.

What each SDK needs

Language You need Command in the clone
Python uv 0.8.4 or newer (it provides Python 3.10 to 3.13) uv sync
JavaScript Node.js 18 or newer npm install
PHP PHP 8.2 or newer and Composer 2 composer install
Java JDK 17 or newer and Maven 3.9 or newer mvn install -DskipTests
.NET .NET SDK 8.0.100 or newer dotnet pack
Dart Dart 3.5 or newer (included with Flutter) dart pub get
Go Go 1.24 or newer go build ./...

Keeping the SDK up to date

Run git pull in the clone. Python, JavaScript, PHP, Dart and Go pick up the change straight away. Java and .NET use a built copy, so run the command in the clone again after you pull.

Troubleshooting

The SDK files are missing after cloning

The clone is on the wrong branch. Clone again with --branch development; the repository's default branch does not carry the SDK.

Java cannot find the SDK

An error such as Could not find artifact com.webcommander:webcommander-sdk means the build step was skipped. Run mvn install -DskipTests in the clone, then build your project again. No extra repository or registry login is needed.
