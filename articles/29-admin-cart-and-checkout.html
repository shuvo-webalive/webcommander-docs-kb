The Admin cart and checkout API lets your software place an order for a customer in steps. You create a cart for the customer with the products to buy, change its lines, set the delivery type and the addresses on its checkout, apply a coupon, a gift card and a delivery date, and then place the order. The cart and its checkout are one session, which every call reaches by its session_id. All nineteen endpoints are available in all seven WebCommander SDKs, under /api/v4/admin/orders/carts and /api/v4/admin/orders/checkout.

Common tasks

You want to Use
Start a cart for a customer Create an admin cart with the customer's customer_id and products, each with a product_id and a quantity, such as {"customer_id": 512, "products": [{"product_id": 101, "quantity": 2}]}. It returns 201 with the priced cart under cart. Keep cart.session.session_id: every other call takes it as session_id
Read the cart again Retrieve an admin cart with the session_id. It returns the lines and totals
Change the products on the cart Add products to an admin cart, Change the quantity of a cart line or Remove a cart line, with the line's cart_item_id. Remove every line from an admin cart empties it, and Replace an admin cart puts a new set of lines on it. Each of these returns the whole cart
Move the cart to another customer Change an admin cart's customer with only customer_id. Sending products there is rejected with 400
See what blocks the order Retrieve a checkout. issues lists what is missing, such as delivery_type required, and is empty when the order can be placed
Set the delivery type and addresses Update a checkout with delivery_type set to shipping, delivery, others_shipping or store_pickup, and a billing_address and shipping_address. It returns the priced checkout, with the shipping and handling cost
Give the customer a coupon Apply a coupon to a checkout with {"code": "SAVE10"}. It returns discounts.coupon.applied_amount, the amount taken off, and the new totals. Remove the coupon from a checkout takes it off again
Pay part of an order with a gift card Apply a gift card to a checkout with {"code": "GIFT-0001"}. totals.gift_card_applied shows what the card pays and totals.due what is left. Remove the gift card from a checkout takes it off again
Choose a delivery date Set a checkout's delivery schedule with the schedule's id and a date. Read it with Retrieve a checkout's delivery schedule, and remove it with Clear a checkout's delivery schedule
Place the order Place the order from a checkout. With no body the order is unpaid. Send payment, with an amount and a payment_method, to record a payment. It returns 201 with the new order, in the same shape as Create an order
Drop a cart you no longer need Delete an admin cart. It returns 204 with no body

Good to know

Placing the order creates a real order. Place the order from a checkout closes the session. Every later call on the cart or the checkout, including a second confirm, is rejected with 410 and the code session_confirmed. A deleted cart is rejected the same way with session_deleted, a second delete included.

Every call takes the cart's session_id. Create the cart and read cart.session.session_id, a value such as PRV-3f2a9c41b7d80e65. The two line calls also take the line's cart_item_id. A session is held for 30 minutes from its last write.

  • Bodies are bare, and customer_id is the customer's own customer_id. Send the fields at the top level, with no wrapper. A field a call does not accept is rejected with 400 and the code unknown_field.
  • Every cart call returns the whole cart, except the delete. The line deletes and removing every line return the cart too. Replacing the cart puts the lines on again, so each gets a new cart_item_id. Adding a product that is already on the cart raises that line's quantity.
  • The order cannot be placed while issues is not empty. Placing it is rejected with 422 and the code checkout_incomplete. A new checkout lists delivery_type as required until you set one.
  • An address you send replaces the whole address. A field you leave out reads "". Shipping and handling follow the shipping address, so send it with delivery_type. A store_pickup has no shipping cost.
  • A shipping or delivery checkout needs a default shipping profile. A new store has none. Create a shipping profile, then make it the store's default_shipping_profile with Update shipping settings: creating the profile alone is not enough.
  • A checkout takes one coupon and one gift card. A second coupon, or a second gift card, is rejected with 409. A code the store does not accept, or a coupon or gift card that is not active, is rejected with 422, with the code invalid_coupon or invalid_gift_card. Removing a coupon or gift card that is not applied returns 404.
  • A coupon lowers the grand total, and a gift card lowers only the amount due. A coupon lowers totals.total_discount and totals.grand_total. A gift card leaves grand_total as it was, sets totals.gift_card_applied and lowers totals.due. It pays only for the cart's own customer, and nothing is spent from it until the order is placed.
  • A delivery date needs delivery_type delivery. With another delivery type, setting a schedule is rejected with 422 and the code delivery_type_not_supported. A schedule that does not apply to the order is rejected with 422 and the code schedule_not_applicable. Clearing a schedule returns 204, also when none was set.
  • The transaction number can go in the body or in a header. Send transaction_no in the confirm body, or as the X-Transaction-No header, which the SDKs send for you. When both are present and differ, placing the order is rejected with 400 and the code header_body_mismatch.
