The Dashboard banners API lets your software work with the announcement banners on the store's admin dashboard. You can list, create, retrieve, update and delete banners, and read the feed the dashboard shows them from. Each banner has a key, a title, a description, up to three tags, a learn_more button, an optional try_it button, a position and an active flag. All six endpoints are available in all seven WebCommander SDKs.

Common tasks

See every banner List dashboard banners. It returns all banners under banners in position order, active and hidden ones, with no paging
See what the dashboard shows now Get the dashboard feed. It returns only the active banners, and the support contact details, online_store and member_label beside them
Read one banner Retrieve a dashboard banner with the banner's key as banner_key
Add a banner Create a dashboard banner with key, title, description and learn_more, such as {"key": "spring_sale", "title": "Spring sale", "description": "Ends Friday.", "learn_more": {"action": "open_link", "label": "Learn more", "url": "https://example.com/"}}. It returns 201 and the banner, which shows on the dashboard of every admin at once
Change a banner or hide it Update a dashboard banner with the banner's key as banner_key and only the fields to change. Send {"active": false} to hide it from the dashboard and keep it in the list
Move a banner Update a dashboard banner with a position. The banner moves there and the others are renumbered
Remove a banner Delete a dashboard banner with the banner's key as banner_key. It returns 204 with no body, and the banners after it move up one position

All endpoints

These six endpoints list, create, retrieve, update and delete dashboard banners and read the dashboard feed, at paths that start with /api/v4/admin/dashboard/banners, except the feed, which is at /api/v4/admin/dashboard/content_info.

Good to know

Banners are store-wide: a banner you create, change or delete shows on the dashboard of every admin. A created banner appears in Get the dashboard feed at once while active is true, and it stays until you delete it. Creating, moving or deleting a banner also changes the position of the banners after it. The store already has banners of its own, so list them with List dashboard banners before you write, and change only banners you created.

Send the fields as they are, with no wrapper. Create and update take the banner's fields at the top level of the body, and the responses return the banner the same way. A field a banner does not have is rejected with 400 and the reason unknown_field, and one 400 response lists every field that failed.

  • Pass the banner's key as banner_key. The key uses lowercase letters, digits and _, starts with a letter, is at most 64 characters and is unique. You choose it when you create the banner and cannot change it. A key that matches no banner is rejected with 404 and the reason not_found.
  • learn_more is required and takes one of two forms. {"action": "open_link", "label": "...", "url": "https://..."} opens a link, and the url must start with https. {"action": "open_modal", "label": "...", "title": "...", "subtitle": "...", "steps": [...]} opens a window with at least one step, each with a title and a description. try_it is optional: {"label": "...", "url": "..."} adds a second button, and null means none.
  • title is 1 to 80 characters, description is 1 to 200, and tags holds at most 3. icon is saved as you send it and is not checked against a list.
  • An update replaces learn_more and try_it whole. An open_modal learn_more sent over an open_link one drops the url, and "try_it": null removes the second button. key cannot be sent, and an empty body is rejected with 400.
  • position counts from 1 over every banner, hidden ones included. Without a position, a new banner goes last. With one, from 1 to one more than the number of banners, the banners from that place move down by one. A position outside that range is rejected with 400 and the reason out_of_range.
