The Email API lets your software send an email from your store to up to 100 addresses in one call. You send your own HTML or plain text, or name an installed plugin's email template and pass its variables. The call returns the addresses the email was sent to and the addresses it could not be sent to. The store keeps no copy of the email. The one endpoint is available in all seven WebCommander SDKs, at /api/v4/admin/email/send.

Common tasks

You want to Use
Send your own HTML email to one or more addresses Send an email with recipients, subject and htmlContent at the top level of the body, such as {"recipients": ["customer@example.com"], "subject": "Your order has shipped", "htmlContent": "<p>Your order is on its way.</p>"}. Leave out the plugin_uuid header. It returns 200 once every message is sent, with status success and the recipients in accepted
Send a plain-text email Send an email with the text in htmlContent and contentType set to text. contentType takes html, text or text/html; any other value is rejected with 400
Copy or blind-copy other addresses Send an email with the addresses in cc or bcc, each a list, such as "cc": ["orders@example.com"]. They count toward the 100 addresses of a call and the 500 addresses a sender can send to each day. The response returns them in cc and bcc
Send from a plugin's email template Send an email with recipients, subject, the template's identifier, such as order-shipped, and its variables as an object in data, such as {"order_no": "1001"}. Leave out htmlContent. Send the installed plugin's uuid in the plugin_uuid header, and authenticate with the plugin's own access token
Find out which addresses the email did not reach Read status, accepted and rejected in the response of Send an email. On 200, status is success and rejected is empty. When the mail server fails the send, the call returns 502 with status failed, an empty accepted, and one object per address in rejected, with email and reason send_failed

Good to know

Each sender can send to 500 addresses a day. Every address in recipients, cc and bcc counts. Past the limit, a valid send is rejected with 429 until 00:00 UTC. error.code is rate_limited, the message is The daily email limit of 500 addresses is reached; try again after 00:00 UTC., and the Retry-After header gives the seconds left until 00:00 UTC. The SDKs' automatic retries do not wait that long, so the call still fails: send again after 00:00 UTC. A send rejected with 400 does not count toward the limit, and an invalid body still gets 400 after the limit is reached.

Send the fields at the top level of the body, in camelCase. Write htmlContent and contentType, not html_content or content_type. The store ignores any field it does not know, snake_case spellings included, and returns no error for it. A body wrapped in email is rejected with 400, and the error's details give recipients and htmlContent the code required.

The plugin_uuid header makes the store authenticate the call as the plugin. With an installed plugin's uuid in the header, an admin access token gets 401, even when you send htmlContent. Leave the header out when you send your own content. A template send needs the header and the plugin's own access token. Write the header name exactly as plugin_uuid, with an underscore. A plugin_uuid field in the body is ignored. An identifier sent without the header is rejected with 400 and the message plugin_uuid header is required to send by identifier, and a uuid no plugin has is rejected with 400 and the message Plugin not found.

  • Send your own content or a template, not both. A body with both htmlContent and identifier is rejected with 400 and the code conflicting_value.
  • One call sends to at most 100 addresses. recipients, cc and bcc together hold at most 100 addresses. More is rejected with 400 and the code too_many, and nothing is sent.
  • A 400 names each problem field. error.code is invalid_request, and each entry in details gives the field in field and the reason in code. An invalid address is named by its position, such as recipients[1] or cc[0], with the code invalid_email. A missing subject is reported only when the body has htmlContent or identifier. An empty body {} returns the message request body is empty. Nothing is sent when the call returns 400.
  • Each address gets one email. Spaces around an address are trimmed, and an address you list twice, in any letter case, is sent once. The response lists it once, in the form you sent first.
  • The body must stay within 1048576 bytes. A larger body is rejected with 413 and the message The request body is larger than 1048576 bytes.
  • POST is the only method. GET, HEAD, PUT, PATCH and DELETE are rejected with 405 and the header Allow: POST, OPTIONS. The store keeps no copy of the email, so there is nothing to read back or delete after a send.
