Every call to the WebCommander API needs an access token. With the legacy sign-in, the token comes from your store, using a client ID, a client secret, a redirect URI and an auth string. The SDKs get the token, keep it and renew it for you. This article explains the credentials, how the SDKs handle the token, and how to request a token yourself.

See Authentication (Legacy) in the developer documentation

New API applications use Authentication (New), which needs only a client ID and a client secret.

Moving to the new sign-in? Only how you get the token changes: it comes from your Hykmah base URL instead of your store. Your base URL stays your store's address, and every API call, path and response stays the same. See Authentication (New).

Your credentials

Credential What it is
Base URL Your store's address, including https://.
Client ID Identifies your integration.
Client secret The secret paired with the client ID.
Redirect URI Sent with the token request.
Auth string Decides which user the token acts as.

Keep your credentials private. The client secret and auth string give access to your store's data. Keep them in environment variables or a secrets manager, never in source code or a shared document.

Set up an SDK

Register your store's credentials once, when your app starts, then build a client wherever you make calls. The developer documentation has a complete registration sample for each language and for cURL. The registration turns on the raise-on-error option, so a failed call raises an error instead of going unnoticed. A 200 response whose body contains "isSuccess": false also counts as a failure.

What the SDKs handle

  • Getting the token. On the first call, the SDK exchanges your credentials for an access token.
  • Caching and renewal. The SDK keeps the token and renews it before it expires, trying the refresh token first.
  • An expired token. If a call returns 401 because the token has expired, the SDK renews the token once and sends the call again.
  • A real refusal. Any other 401, such as a wrong old password when you change a password, is returned to you and not retried, so a write is never sent twice.

Requesting a token yourself

With cURL or any HTTP client, send a POST request to /api/v4/oauth2/token on your store's base URL. The body is JSON with these fields:

Field Value
grant_type client_credentials
client_id Your client ID.
client_secret Your client secret.
redirect_uri Your redirect URI.
auth_string Your auth string.

A successful request returns 201 Created with these fields:

Field Meaning
access_token The token to send with each call.
expires_in Seconds until the token expires.
refresh_token Exchanged for a new access token when this one expires.

Send the access token in an Authorization: Bearer header on every API call.

Try it in the documentation

Open Get an access token (Legacy), click Try it, set the store to your store's host name, choose client_credentials, fill in your credentials and send the request. Copy the access token from the response. Then open any endpoint, set the same store, paste the token into Authorization and send. These calls run against your real store, so use test data.
