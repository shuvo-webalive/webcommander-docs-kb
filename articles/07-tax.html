The Tax API lets your software manage a store's tax setup. You can list, create, update and delete tax codes, tax rules, tax zones, tax profiles, custom tax profiles and country taxes, and change the store's tax settings. All forty endpoints are available in all seven WebCommander SDKs.

Tax has seven parts, and each has its own reference: Tax codes, Tax rules, Tax zones, Tax profiles, Custom tax profiles, Country taxes and Tax settings.

Common tasks

You want to Use
Change the store's tax message or default tax code Update tax settings, with only the fields you change, such as tax_message, inside settings
Add a new tax rate Create a tax code with a name and a rate
Change the rate of a tax code Retrieve a tax code, passing the tax code's id as tax_code_id, then Update a tax code with the new rate and the tax code's current priority and resolver_type
Set the tax rate for a country Create a country tax with the country's code, such as NZ, in country_code. To change the rate later, use Update a country tax with a new tax_rate, passing the country tax's id as country_tax_id
Group countries, states and post codes into a tax zone Create a tax zone with a name. Send each country in countries as {"id": 12}, where 12 is the country's id from the countries of a zone in List tax zones. Send each state in states the same way, and the post codes in post_code as a flat list
Make a tax profile the store's default Update a tax profile with default: true, passing the tax profile's id as tax_profile_id. The tax settings then show that profile's id in default_tax_profile

Good to know

Some updates reset the fields you leave out

Updates to tax profiles, tax rules, country taxes and tax settings change only the fields you send. Three others do not. An update to a tax code sets priority to 0 and resolver_type to flat if you leave them out. Replacing a custom tax profile sets description to null if you leave it out. An update to a tax zone empties countries, states and post_code if you leave them out, and sets use_radius to false if you leave it out. Custom tax profile and tax zone updates also need name every time. For these three, send the current values of every field you want to keep.

A failed request can make the next request fail too

When a tax request is rejected, the next request on the same connection can fail in the same way, even if it is correct. After a 404, the next request for one record can return 404 for a record that exists, even in another part of Tax, and a delete returns that 404 and deletes nothing. After a list is rejected for its limit or offset, the next list returns the same 400. The request after that works normally. If a call fails straight after another failed call, send it again, and read the record back to confirm a change or a delete.

Put each write inside the right key

For every create and update, send the fields inside one key named after the record: tax_code, tax_rule, tax_zone, tax_profile, custom_profile or country_tax, for example {"tax_code": {"name": "LUXURY", "rate": 15.0}}. Tax settings are different: the read returns them under tax_settings, but an update takes them under settings. A body without the right key is rejected with 400.

  • Lists return up to 20 records at a time. A larger limit still returns 20. To get more, raise offset by the number of records each page returned until you reach pagination.total. q does not filter any tax list.
  • The Check endpoints do not tell you whether a record exists. They return 200 even when no record has the id you pass as tax_code_id, tax_rule_id, tax_zone_id or tax_profile_id. Use the matching Retrieve endpoint instead, which returns 404 when no record has that id.
  • You cannot set a tax rule's tax code or zones. A create or update accepts code, zones, decimal_point and rounding_type but does not store them. A rule you create has code: {} and zones: [].
  • Move the default tax profile rather than deleting it. At most one tax profile is the default. To change it, send default: true in Update a tax profile for the new default. Sending default: false leaves the flag where it is. If you delete the default profile, default_tax_profile in the tax settings still holds the deleted profile's id, and an update to the tax settings cannot send that value back.
  • Send a tax zone's post codes as a flat list. Send ["2000", "3000"] in post_code. The zone returns them as [["2000"], ["3000"]], and sending that nested form back fails with 500.
  • Tax settings save some values without checking them. default_country, default_tax_code and custom_tax_profile_id (a custom tax profile's id) are saved even when they match nothing, so check them before you send them.
