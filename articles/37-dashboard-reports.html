The Dashboard reports API lets your software read the three reports behind the admin dashboard for a period: the quick report, the sales report and the summary. Each report also has a HEAD form that returns 200 with no body. All six endpoints are available in all seven WebCommander SDKs.

Open the Dashboard reports reference

Common tasks

You want to Use
Get the headline figures for a period Get the quick report. It returns the 27 kpis, orders, sales, customers, products, page_views, view_report and 12 trends. Send kpis such as total_sales,aov to get only those metrics, in that order
See which pages or products are viewed most Get the quick report with entity_name set to page or product. view_report.items ranks them by views
Get sales by day or month Get the sales report. It returns rows and totals, grouped by day for a period of about a month or less and by month for a longer one. Add breakdown=true for orders, shipping, tax, discounts, refunds and the top product, and sort and order to sort the rows
Get an overview in one call Get the summary report. It returns totals, orders by month, sales rows, the most visited and best selling products, and order_updates
Choose the period Send duration such as last_12_months to any report, or start_date with end_date as YYYY-MM-DD. Without either, the period is last_30_days
Check that a report can be read Check the quick report, Check the sales report or Check the summary report. Each returns 200 with no body after it checks the same query as its report

All endpoints

These six endpoints read the quick report, the sales report and the summary, and check each one, at paths that start with /api/v4/admin/dashboard/reports.

Good to know

Every report takes the same period. duration is one of today, yesterday, last_24_hours, last_7_days, last_30_days, this_month, last_month, last_3_months, last_6_months, last_12_months, last_24_months, last_36_months, last_48_months, last_60_months or custom, which the response uses when you send dates. period in every response shows the days covered, the days before them that previous_value covers, the time_zone and the currency.

A bad value is rejected with 400, and one response lists every field that failed. A duration outside the list, a duration sent twice, and a start_date without an end_date (or the reverse) are rejected with the reason invalid_request. sort, order, entity_name, kpis and breakdown have their own values, and compare_previous takes true or false. A query parameter a report does not know is ignored.

  • A period with no sales has no rows. Get the sales report returns rows as an empty list and still returns totals. Lists such as view_report.items can be empty too.
  • Do not expect two reports to give the same total. In the same call, orders.count and the total_orders tile can differ, and the sales report covers only paid orders.
  • The HEAD calls check the query, not the data. A HEAD call returns 200 with no body, and a bad value in the query is rejected with 400, as it is for the GET.
