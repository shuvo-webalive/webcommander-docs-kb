The Domain aliases API lets your software manage a store's domain aliases: the extra hostnames, such as shop.example.com, that the store responds to. You can list the aliases, add new ones and delete the ones you no longer need. All four endpoints are available in all seven WebCommander SDKs.

Good to know

Send the hostname as a plain string

The create body is {"alias": "shop.example.com"}. The create response returns the new alias as an object under the same alias key. Do not send that shape back: a body such as {"alias": {"alias": "shop.example.com"}} is rejected with 400 invalid_hostname.

You cannot read or change one alias on its own

You can list, create and delete aliases. Reading or updating a single alias returns 405, and an update changes nothing. To find one alias, page through List domain aliases and look for its hostname in alias. There is no call that counts aliases. To get the number of aliases, read pagination.total in the list response.

  • The list returns up to 20 aliases at a time. A larger limit is capped at 20. To get more, send the next page number or a higher offset while pagination.has_next is true. You cannot search or sort the list: any parameter other than limit, offset, page and field_metadata, such as q or sort, is rejected with 400 unknown_parameter.
  • Each hostname can be added only once, whatever its letter case. If another alias already has the hostname, even in a different letter case, the create is rejected with 409 and the message alias already exists. The store keeps the letter case you send.
  • The hostname must be well formed. A hostname with a space in it, a scheme such as https://, an underscore or a leading hyphen is rejected with 400 invalid_hostname. So is an alias that is a number or a list. Spaces before or after the hostname are removed.
  • The site settings show the same hostnames. They appear under domain_settings.aliases as a read-only list. Creating an alias adds its hostname to that list, and deleting the alias removes it.
