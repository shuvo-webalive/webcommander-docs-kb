The Dashboard KPIs API lets your software see which metrics the dashboard's KPI tiles can show, read the tiles in use with their figures for a period, and choose which 2 to 5 tiles the dashboard shows. All three endpoints are available in all seven WebCommander SDKs.

Open the Dashboard KPIs reference

Common tasks

You want to Use
See which metrics a tile can show List KPI options. It returns the 27 metrics in five groups (ecommerce, content, blog, bookings and courses), each with its key, code, label, format and in_use, and the keys now selected
Read the tiles with their figures Get the KPI selection. It returns the tiles in selected, each with value, previous_value, change_percent and direction, for last_30_days or the period you send
Read the figures for another period Get the KPI selection with duration set to a value such as last_7_days, or with start_date and end_date as YYYY-MM-DD
Choose the tiles Update the KPI selection with {"metrics": ["total_sales", "total_orders", "aov"]}, the full list of 2 to 5 metric keys in tile order. It returns the same fields as the read, with the tiles in the order you sent

All endpoints

These three endpoints list the metrics, read the KPI tiles and choose the tiles, at paths that start with /api/v4/admin/dashboard.

EndpointMethodPath
List KPI options
Returns every metric a KPI tile can show, by group, and the keys now selected.		GET…/dashboard/kpi_options
Get the KPI selection
Returns the KPI tiles the dashboard shows, with their figures for a period.		GET…/dashboard/kpi_selection
Update the KPI selection
Sets the 2 to 5 KPI tiles the dashboard shows, for every admin, and returns them.		PUT…/dashboard/kpi_selection

Good to know

Updating the KPI selection changes the tiles on the dashboard of every admin. It writes the KPI tiles of the store's default dashboard layout, so the change shows at once for everyone, and the layout's updated_at moves. Before you call Update the KPI selection, read the keys in selected from List KPI options, so you can send them back to restore the tiles.

Select metrics by key, not by code. For most metrics the two are the same. For some they differ, such as key aov with code average_order_value. The update takes the key.

  • The dashboard shows 2 to 5 tiles. min and max in List KPI options give the limits. A list of fewer than 2 or more than 5 keys is rejected with 400 and the reason invalid_count, a repeated key with duplicate_value, an unknown key with invalid_enum, and a missing metrics with required.
  • The figures follow the period you send. The read and the update take duration (the default is last_30_days) or start_date with end_date. A bad value, or one date without the other, is rejected with 400. change_percent is null when previous_value is 0, and value is always a decimal, such as 19.0.
  • The update ignores fields other than metrics. A body with other fields still returns 200.
