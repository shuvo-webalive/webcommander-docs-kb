The Dashboards API lets your software work with the dashboard layouts of a store's admin. A layout chooses which sections the dashboard shows, in what order, and which KPI tiles it starts with. You can list, create, retrieve, update and delete layouts. Each layout has a name, a default flag, standard_sections, customisable_sections and kpis. All five endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
See which layouts the store has List dashboard layouts. It returns every layout under dashboards with its id, name and default, with no paging. Exactly one layout has default set to true
Read a layout's sections and KPI tiles Retrieve a dashboard layout with the layout's id as dashboard_id. It returns standard_sections, customisable_sections and kpis
Add a layout Create a dashboard layout with {"name": "Weekly"}. The new layout is a copy of the default layout, or of the layout whose id you send as copy_from. Send kpis and customisable_sections to change the copy. It returns 201 and the whole layout
Hide a section Update a dashboard layout with {"standard_sections": [{"key": "announcement", "visible": false}]}. Every section you leave out stays as it is. It returns the whole layout
Reorder the sections or the tabs Update a dashboard layout with a position on a customisable section, or on a tab inside section_tabs. The others move to fit
Change a layout's KPI tiles Update a dashboard layout with kpis, the full list of 2 to 5 metric keys in tile order, such as ["total_sales", "total_orders"]
Make a layout the default Update a dashboard layout with {"default": true}. This changes the dashboard for every admin, so read Good to know first
Remove a layout Delete a dashboard layout with the layout's id as dashboard_id. It returns 204 with no body

All endpoints

These five endpoints list, create, retrieve, update and delete dashboard layouts, at paths that start with /api/v4/admin/dashboards.

EndpointMethodPath
List dashboard layouts
Returns every dashboard layout with its id, name and whether it is the default.		GET…/dashboards
Create a dashboard layout
Creates a layout as a copy of the default layout and returns it with its id.		POST…/dashboards
Retrieve a dashboard layout
Returns the layout whose id you pass as dashboard_id, with its sections and KPI tiles.		GET…/dashboards/{dashboard_id}
Update a dashboard layout
Changes only the fields you send and returns the whole layout.		PATCH…/dashboards/{dashboard_id}
Delete a dashboard layout
Deletes the layout whose id you pass as dashboard_id and returns no body.		DELETE…/dashboards/{dashboard_id}

Good to know

Creating a layout changes the store, and making a layout the default changes the dashboard for every admin. A layout you create is saved to the store and stays there until you delete it. Sending "default": true moves the store's default layout to the layout you name, and every admin then sees that layout. Before you do, note which row of List dashboard layouts has default set to true, so you can set it back.

Send the fields as they are, with no wrapper. Create and update take the layout's fields at the top level of the body, such as {"name": "Weekly"}, and the responses return the layout the same way. A body with no fields is rejected with 400, and a field the layout does not have is ignored.

A new layout is a copy of the default layout. Create a dashboard layout copies the default layout's sections and KPI tiles, or those of the layout you name in copy_from, and then applies the customisable_sections and kpis you send. A new layout is not the default unless you send default set to true.

  • An update changes only what you send, and sections are matched by key. The four standard sections (announcement, performance, activity and contact) take only visible, and contact cannot be hidden. The customisable sections (setup_guide, section_tabs and seo) also take a position. Send the tabs of section_tabs as tabs and the parts of seo as parts, each with its key.
  • kpis is the full list of the layout's tiles. It holds 2 to 5 distinct metric keys in tile order, and it replaces the tiles the layout has. A list of 1 or of more than 5 keys is rejected with 400 and the reason invalid_count.
  • A layout name is unique and at most 60 characters. A name that another layout already has is rejected with 409, the reason conflict and the detail code name_taken. A blank name or one longer than 60 characters is rejected with 400. Sending "default": false for the default layout is rejected with 409; make another layout the default instead.
  • Pass the layout's id as dashboard_id. The id is a UUID. An id that matches no layout is rejected with 404, the reason not_found and the detail on the field dashboard_id.
