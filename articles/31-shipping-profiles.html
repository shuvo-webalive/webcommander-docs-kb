The Shipping profiles API lets your software work with a store's shipping profiles. A shipping profile is a named set of shipping rules, with a rule_preference that decides which rule applies when several match, and one profile is the store's default. You can list, count, create, retrieve, replace, update and delete profiles, and build a whole profile with its rules and rates in one call. All eleven endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get every profile, or only the default one List shipping profiles, page by page. Each call returns up to 20 profiles under shipping_profiles, newest first, or up to the limit you send, from 1 to 100. Send search=metro to get the profiles whose name contains that text, and default=true to get only the default profile. Count shipping profiles takes the same filters and returns the number of matches as total
Add a profile Create a shipping profile with the fields inside shipping_profile, such as {"shipping_profile": {"name": "Metro profile", "shipping_rules": [31]}}. Only name is required. It returns 201 and the new profile, with its id. Pass that id as shipping_profile_id to retrieve, change or delete the profile
Build a profile with its rules and rates in one call Create a shipping profile with the wizard with shipping_rules, a list of rules that each hold a shipping_rate. It creates the profile, the rules and the rates together. It returns 201 for a new profile name. When a profile already has that name, it adds the new rules to that profile and returns 200
Change a profile's description, rule preference or rules Update a shipping profile with the profile's id as shipping_profile_id and only the fields to change inside shipping_profile, such as {"shipping_profile": {"rule_preference": "lowest_shipping_cost_rule"}}. Every field you leave out keeps its value. To replace the whole profile, use Replace a shipping profile
Make a profile the store default Update a shipping profile with {"shipping_profile": {"default": true}}. The profile you name gets default set to true, and the profile that was the default gets false
Remove a profile Delete a shipping profile with the profile's id as shipping_profile_id. It returns 204 with no body. The profile's rules stay in the store. You cannot delete the default profile

Good to know

Making a profile the default changes the default for the whole store. Exactly one profile has default set to true. Sending default as true on a create or an update moves the default to that profile and sets default to false on the old one. Before you do, find the current default, the profile in List shipping profiles with default=true, so you can set it back. Sending default as false on the default profile, and deleting it, are both rejected with 409 and the reason default_profile. Make another profile the default first.

Send the fields inside shipping_profile. Create, replace, update and the wizard take {"shipping_profile": {...}}. A body without the wrapper is rejected with 400, and so is a field the profile does not have or an id in the body. Responses return the profile inside shipping_profile.

  • rule_preference decides which rule applies when several match. It is product_assigned_rule, the default, lowest_shipping_cost_rule or highest_shipping_cost_rule. The short codes hp, lsc and hsc are accepted on a write, and the profile returns the long names. Any other value is rejected with 400.
  • shipping_rules is the whole list of rule id values. Each rule appears once, and an unknown or repeated id is rejected with 400. An update with "shipping_rules": [] takes every rule off the profile, and the rules stay in the store.
  • PUT replaces a profile, and PATCH changes only the fields you send. Replace a shipping profile needs name, description, rule_preference and shipping_rules. description takes null. Each field you leave out is named in the 400 response with the code required.
  • Profile names are unique, in any letter case. A name that another profile has is rejected with 409 and the code duplicate. Send suggest_name as true on a create to get the next free name, such as Metro profile(1), instead.
  • The wizard saves nothing when any value is bad. Each rule needs a name. A zone is {"id": 5} for an existing zone, or {"name": "Inner West"}, which creates a new zone. The response does not list the zones the call created: read them from the zones of each rule with Retrieve a shipping rule. A GET or HEAD on the wizard path is rejected with 405.
  • You can file a profile under a transaction number. Send transaction_no inside shipping_profile, or the X-Transaction-No header on a create. When you send both, the header wins.
  • A listing returns 20 profiles per call unless you send limit. limit takes 1 to 100: 0, a value above 100 and a value that is not a number, such as all, are rejected with 400. To get more, send a higher offset while pagination.has_next is true. sort takes id, name, description, rule_preference, created_at, updated_at or transaction_no, and order takes asc or desc.
