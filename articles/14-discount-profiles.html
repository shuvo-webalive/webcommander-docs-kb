The Discount profiles API lets your software work with a store's discount profiles. You can list, create, retrieve, replace and delete profiles, generate coupon codes for a profile, and assign a coupon code to a customer by email address. Each profile has one block of discount details, chosen by its discount_details_type: amount, shipping or product. All seven endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Find discount profiles by name or by profile type List discount profiles with name to keep the profiles whose name contains that text, in any letter case, or with type to keep one profile type, such as offer_coupon. Each call returns at most 20 profiles in discount_profiles. To get the next page, raise offset by pagination.limit while pagination.has_next is true
Add a discount profile that uses coupon codes Create a discount profile with these fields at the top level of the body: a name, discount_details_type set to amount, an amount_details block such as {"type": "single", "apply_to": "total_order", "single_amount": 40, "single_amount_type": "PERCENT"}, and is_apply_coupon_code set to true. Send a default_coupon_code to choose the code, or leave it out and the store generates one. It returns 201 with the new profile under discount_profile. Pass the new profile's id as discount_profile_id to retrieve, replace or delete the profile, or to generate coupon codes for it
Change a profile's amount, dates or limits Retrieve a discount profile, then Replace a discount profile with the profile's id as discount_profile_id. Send every flag, date and limit you want to keep, because a replace resets the ones you leave out. Always send the details block of the profile's discount_details_type too. The response returns the profile after the replace
Generate coupon codes for a profile Generate coupon codes with the profile's id as discount_profile_id and a body such as {"requested_codes": 3}. The profile must have is_apply_coupon_code set to true. The response returns the new codes in codes
Give a coupon code to a customer Assign a coupon code to a customer with the coupon's code and the customer's email, such as {"code": "A1B2C3D4E5", "email": "jane.citizen@example.com"}. The email address must belong to an existing customer. It returns 201 with status set to success
See a profile's coupon codes and which customer has each one Retrieve a discount profile with the profile's id as discount_profile_id. In the response, customer_coupons lists each generated code with the customer_email of the customer it is assigned to, or "" until a customer is assigned. The profile's default_coupon_code is not in this list
Remove a discount profile and its coupon codes Delete a discount profile with the profile's id as discount_profile_id. It deletes the profile's coupon codes with it and returns 204 with no body

All endpoints

These seven endpoints list, create, retrieve, replace and delete discount profiles and generate coupon codes for a profile at paths that start with /api/v4/admin/discount_profiles, and assign a code to a customer at /api/v4/admin/discount_coupons/assign-customer.

Good to know

Replacing a discount profile resets every flag, date and limit you leave out of the body. On PUT, every is_* flag you leave out becomes false, start_date becomes null, end_date becomes "", and maximum_use_count, maximum_use_customer_count and maximum_discount_allowed_amount become null. name, type, default_coupon_code, display_text_coupon, display_text_cart, display_text_partial_discount_condition, invoice_note and exclude_products keep their values when you leave them out. Always send the details block of the profile's discount_details_type: without it the call returns 500 and changes nothing. To change one value, Retrieve a discount profile first and send back every value you want to keep. A PATCH on the profile's path is rejected with 405.

Send a profile at the top level of the body, not inside discount_profile. Create and replace read the fields from the top level of the body, and responses return the profile inside discount_profile. A create wrapped in discount_profile is rejected with 400 and the message name: Discount profile name is required. A create drops any top-level field the store does not know, without an error.

Each profile has one details block, chosen by discount_details_type. amount uses amount_details, shipping uses shipping_details and product uses product_details. A profile returns only its own block, and the other two keys are absent. A create with a missing or empty block is rejected with 400. A block without a field the store needs returns 500 with the reason internal_error and stores nothing: a single amount_details needs type, apply_to, single_amount and single_amount_type, a shipping_details needs apply_to and minimum_qty_on, and a product_details needs free_product_min_qty_on. A product_details with keys the store does not recognise can return 500 and still store the profile, so after a 500, list profiles by name before you send the create again. An exclude_products entry that is not an existing product's id also returns 500 and stores nothing.

  • A replace skips most of the checks a create makes. Replace a discount profile stores these values as sent: a type other than customer, promote_product, offer_incentive_and_sell_more or offer_coupon, a single_amount_type other than FLAT or PERCENT, a negative single_amount, a PERCENT amount above 100, and an end_date before start_date. A start_date that is not a date is stored as null. Check these values before you send a replace. A replace returns 400 only when name contains <, >, javascript: or expression(), or when is_specify_end_date or is_imported_coupon is a string. When the body sets is_apply_coupon_code to true, the response shows customer_coupons as [] even when the profile has coupon codes: retrieve the profile to read them.
  • Profile names are unique in any letter case. A create with a name that another profile already has, in any letter case, is rejected with 409 and the message Discount Name already exists. A replace with a blank name, a name over 255 characters or a name another profile has returns 500, and the profile does not change.
  • Dates go in as yyyy-MM-dd HH:mm:ss and come back in UTC. The store reads start_date and end_date in its own time zone and returns them converted to UTC as yyyy-MM-ddTHH:mm:ss, with no zone suffix, so the time you read back can differ from the time you sent. A profile without dates returns start_date as null and end_date as "". A create stores end_date only when the same body sets is_specify_end_date to true.
  • The listing returns at most 20 profiles per call and ignores unknown query parameters. A larger limit is capped at 20. To get the next page, raise offset by pagination.limit while pagination.has_next is true. The listing reads only limit, offset, page, sort, dir, type, name and field_metadata. Any other parameter, such as q, search or is_active, is ignored, so a misspelt filter returns the unfiltered listing. The listing sorts in descending order when dir is absent, empty or exactly desc, and in ascending order for any other value, DESC included, so send asc or desc in lower case. There is no count endpoint: read pagination.total for the number of profiles that match your filters.
  • Coupon codes belong to a profile. Generate coupon codes adds codes only to a profile that has is_apply_coupon_code set to true, at the end of its customer_coupons with an empty customer_email. On any other profile it is rejected with 400 and the message Coupon code not allowed. Assign a coupon code to a customer gives a code to a customer by email address, matched in any letter case. When no customer has that email, it returns 400 with detailsMessage set to customer.not.found. A code that is already assigned moves to the customer you name. The assign call returns its errors as a flat body with status, message and detailsMessage, not inside the error object the other calls return. Deleting a profile deletes its codes, and assigning one of them then returns 400 with detailsMessage set to coupon.not.found.by.code.
  • After a rejected read, the client's next call to the same endpoint can return the same error. After a listing is rejected with 400, the next listing on that client can return the same 400, even when its own parameters are valid. Retrieve a discount profile returns 404 when no discount profile has the discount_profile_id you send, and 400 when the discount_profile_id you send is not a number. After either error, the next read of an existing profile on that client can return the same error. A client created after the rejection is not affected, so send the call again on a new client.
