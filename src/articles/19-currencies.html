The Currencies API lets your software work with a store's currencies. You can list, count, create, retrieve, replace, update and delete currencies, and choose the store's base currency. Each currency has a name, a three-letter code, a symbol, a country, a conversion_rate against the base currency, a rounding rule, a precision and an active flag. All eleven endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get every currency, or only the active ones List currencies, page by page. Each call returns up to 20 currencies under currencies, or up to the limit you send, from 1 to 100. Send active=true to get only active currencies, or active=false to get only inactive ones
Find a currency by its name or code, or count the matches List currencies with search, such as search=dollar. It returns the currencies whose name or code contains that text, in any letter case. Count currencies takes the same search and active and returns the number of matches as total
Add a currency Create a currency with the fields at the top level of the body, such as {"name": "Example Dollar", "code": "XEX", "symbol": "$", "country": "NZ", "conversion_rate": 1.2345}. name, code and symbol are required. It returns 201 and the new currency under currency, with the new currency's id. Pass the currency's id as currency_id to retrieve, change or delete the currency
Change a currency's rate, or any one field Update a currency with the currency's id as currency_id and only the fields to change, such as {"conversion_rate": 2.5}. Every field you leave out keeps its value. It returns the currency after the change
Make another currency the base currency Set the base currency with the currency's id as currency_id and no body. The currency must be active. It returns the new base under currency and the currency that was the base under previous_base. It also sets the new base's conversion_rate to 1 and divides every other currency's conversion_rate by the new base's old rate
Find out whether a currency changed without reading it Check a currency with the currency's id as currency_id. It returns headers only, with the same ETag that Retrieve a currency returns, and the ETag changes when the currency changes. It returns 404 when no currency has that currency_id
Remove a currency Delete a currency with the currency's id as currency_id. It deletes the currency permanently and returns 204 with no body. If the currency is the base currency, make another currency the base first

All endpoints

These eleven endpoints list, count, create, retrieve, replace, update and delete the store's currencies, and choose the base currency, at paths that start with /api/v4/admin/currencies.

{{endpoints:currencies}}

Good to know

Setting the base currency changes the conversion_rate of every currency in the store. Set the base currency sets the new base's conversion_rate to 1 and divides every other currency's rate, inactive ones included, by the new base's old rate. Every currency gets a new updated_at and ETag. Rates are kept to 6 decimal places, so switching back does not always restore a rate exactly. Product base_price values do not change. The response returns only the new base's id, name, code and base, so retrieve the currency to read its other fields. Send no body: any body, {} included, is rejected with 400.

Send the fields at the top level of the body, not inside currency. Create, replace and update all take the currency's fields directly in the body, such as {"conversion_rate": 2.5}. A body wrapped in currency is rejected with 400. The error's details give currency the reason unknown_field, and name, code and symbol the reason required. The responses return the currency inside currency. Leave out the currency's id: a body that sends it is rejected with 400 and the message must not be present - the URL names the currency. base and updated_at are rejected with 400 too, with the message is not a currency field.

PUT replaces a currency, and PATCH changes only the fields you send. Replace a currency resets every field you leave out: conversion_rate to 1, rounding to nearest, precision to 2, active to true and country to the store's default country. To change one field, use Update a currency. An update with an empty body is rejected with 400 and the message request body is empty.

  • Exactly one currency is the base, and you cannot replace, update or delete it. PUT and PATCH on the base currency are rejected with 400 and the message The base currency is read-only - make another currency the base first. DELETE on it is rejected with 409 and the message The base currency cannot be deleted. Make another currency the base first with Set the base currency. That call is the only way to move the base, and it rejects an inactive currency with 400 and the message An inactive currency cannot be the base currency - activate it first.
  • A listing returns 20 currencies per call unless you send limit. limit takes 1 to 100, and pagination.limit shows the page size applied. To get more, send a higher offset while pagination.has_next is true. page is rejected with 400. Without sort, currencies come in ascending order of the currency's id, and the base currency is not moved to the top.
  • q does not filter the listing. The store ignores q and returns every currency, so send search instead. search matches name and code only: it does not search symbol or the country.
  • code is any three letters, stored in upper case. The store does not check it against ISO 4217, even though field_metadata describes it as an ISO 4217 code. code and name must each be unique: a code or name another currency already has is rejected with 409. name is compared without regard to letter case.
  • Rates are stored to 6 decimal places. conversion_rate must be above 0 and at most 999999999. A rate of 1.234567891 is stored as 1.234568, so read the rate from the response.
