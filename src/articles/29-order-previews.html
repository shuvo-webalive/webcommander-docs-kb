The Order previews API lets your software price an order before it places it. You start a preview with the products, the customer and the delivery type, and the store returns the lines, tax, shipping and handling, and the grand total. You can apply a coupon or a gift card to see the lower total, and then place the order from the preview. Starting a preview creates no order. All seven endpoints are available in all seven WebCommander SDKs, under /api/v4/admin/orders/preview.

Common tasks

You want to Use
Price an order without placing it Start an order preview with products, each with a product_id and a quantity, and the customer's customer_id, such as {"customer_id": 512, "products": [{"product_id": 101, "quantity": 2}]}. It returns 201 with the priced preview under order, and the preview's order.session.session_id, which every other call takes as preview_session_id
Price an order for a delivery type Start an order preview with delivery_type set to delivery, others_shipping, shipping or store_pickup. It is shipping when you leave it out, and store_pickup sets the shipping cost to 0
Read a preview again Retrieve an order preview with the session_id as preview_session_id. It returns the same shape as starting the preview, with any coupon or gift card you applied, and does not extend the preview's time
Show a customer the price with a coupon Apply a coupon to a preview with {"code": "SAVE10"}. It returns discounts.coupon with the amount taken off, and the new totals. To take the coupon off again, use Remove the coupon from a preview, which returns 204 with no body
Pay part of an order with a gift card Apply a gift card to a preview with {"code": "GIFT-0001"}. totals.gift_card_applied shows what the card pays and totals.due what is left. To take the card off again, use Remove the gift card from a preview
Place the order from a preview Place the order from a preview. With no body the order is unpaid. Send payment, with a payment_method, to record a payment, such as {"payment": {"amount": 10, "payment_status": "success", "payment_method": "manual"}}. It returns 201 with the new order, in the same shape as Create an order

Good to know

Placing the order creates a real order. Place the order from a preview closes the preview. Every later call on it, including a second confirm, is rejected with 410 and the detail session_confirmed.

A preview lasts 30 minutes from its last change. order.session.expires_at is 30 minutes after the preview started. Each time you apply or remove a coupon or a gift card, it moves to 30 minutes after that call; reading the preview does not move it. Start a new preview when it has expired.

The path takes the session_id. Start a preview and read order.session.session_id, a value such as PRV-3f2a9c41b7d80e65. Every other call takes it as preview_session_id. An unknown value returns 404.

  • Send only product_id and quantity for each product. The store reads the prices itself. A price or product_name in a product line, or a body field the call does not accept, is rejected with 400 and the reason unknown_field.
  • Send a customer or a billing address. With customer_id alone, the preview uses the customer's saved addresses. Without customer_id and billing_address, the call is rejected with 400, and so is a preview with a product to ship and no shipping address.
  • A preview takes one coupon and one gift card. A second coupon is rejected with 409 and the detail coupon_already_applied, and a second gift card with gift_card_already_applied. Remove the applied one first.
  • A coupon must apply to every customer and every product. When you create its discount profile, send is_applied_to_all_customers true, is_applied_to_all_products true and category []. Otherwise the code is rejected with 422 and the message Invalid Code. The code you apply is the profile's default_coupon_code.
  • A gift card pays only for the customer whose email address it holds. The card's email must equal the email of the customer record you previewed, not the billing address's email. A card with no balance, past its end date, inactive or unpaid is rejected with 422 and the detail invalid_gift_card. The preview lowers due, leaves grand_total as it was, and spends nothing from the card.
  • The coupon and gift card calls return only part of the preview. They return session, discounts and totals. Retrieve the preview for the lines and the shipping.
  • A payment above the amount due is rejected. When you place the order, a payment.amount over the amount due returns 422 with the detail payment_exceeds_due, and the preview stays open. An amount below the grand total makes the order partial, and an amount equal to it makes it paid.
