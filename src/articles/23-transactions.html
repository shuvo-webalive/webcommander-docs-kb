The Transactions API lets your software read back the transaction numbers stamped on a store's records. When a create call sends a transaction_no, the store stamps that number on the record it creates. With this API you list those numbers, count each number's records by record type, and list the records of one type, such as the products stamped with one number. You can only read transaction numbers. All six endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get every transaction number on the store, page by page List transactions. It returns the numbers under transactions in ascending order of transaction_no, 20 per call, or up to the limit you send, at most 200. Each row has the number in transaction_no and how many records it is stamped on in total_records. Send a higher offset while pagination.has_next is true
Find out how many records one number is stamped on List transactions with the number as the transaction_no query parameter, such as transaction_no=IMPORT-2026-0001. It returns only that number's row, with its total_records, and no pagination block
See how many records of each type one number is stamped on Retrieve a transaction with the number as the transaction_no path parameter. It returns total_records and by_type: always 15 rows in the same order, one per record type, each with type and count. It returns 404 when no record is stamped with the number
List the products stamped with a number List the records of a transaction with the number as the transaction_no path parameter and type=product. It returns the products under items, newest first, 20 per call unless you send limit. Each item has the product's id, name, sku and url
Get the full records instead of the short form List the records of a transaction with detail=full, such as type=category&detail=full. Each item is then the record as its own retrieve call returns it, without the wrapping key
Open one of the records Call the path in the item's url, such as /api/v4/admin/products/207. For a category, pass the item's id as category_id to Retrieve a category. An order's url ends with the order's order_no, not the order's id: the orders API takes the order_no as order_id
Find out whether any record is stamped with a number Check a transaction with the number as the transaction_no path parameter. It returns 200 with headers only when at least one record is stamped with it, and 404 when none is

All endpoints

These six endpoints list the store's transaction numbers, return one number's record counts by type, list its records of one type, and return the headers of each, at paths that start with /api/v4/admin/transactions.

Good to know

Do not follow url, items_url or pagination.next_page for a number that contains a space. The store writes a space in these links as +, then reads a + in a path as a literal +. A url link then returns 404, and an items_url link returns 200 with no records. Pass the number as transaction_no to the SDK function instead: the SDKs percent-encode it, so a space reaches the store intact. For the next page, call the SDK function with the next offset.

Do not use / in the transaction numbers you send. A number that contains / cannot be read. The request is rejected with 400 and an HTML page, Invalid URI: [The encoded slash character is not allowed], not a JSON error, before it reaches the API.

transaction_no matches exactly, letter case included. Send the number exactly as the create call sent it. import-2026-0001 returns 404 with the error code not_found and the message transaction not found when the number was stored as IMPORT-2026-0001. The store trims surrounding spaces off a number when it stores it, so send the number without them.

An unknown number returns an empty list, not 404, when you list its records. List the records of a transaction returns 200 with an empty items list and a total of 0 both for a number no record is stamped with and for a type with no records. To tell the two apart, use Check a transaction or Retrieve a transaction, which return 404 for a number no record is stamped with.

A record you move to the trash stays counted. After you delete a category stamped with a number, using Delete a category, the number's total_records, its category count and the category's row under items do not change. The number also stays in the listing. A record that a delete removes outright, such as a custom tax profile, is no longer counted under its number, and a number left with no records returns 404.

  • You can only read transaction numbers. Every path accepts GET, HEAD and OPTIONS. POST, PUT, PATCH and DELETE are rejected with 405, the error code method_not_allowed and the message HTTP method not allowed for this endpoint. To stamp a number, send transaction_no on the create call that makes the record.
  • Send type every time you list or check a number's records. It takes one of the 15 type names in lower case, such as product, customer, order or category. A missing type is rejected with 400 and the message type query parameter is required. A name in upper case, an unknown name or a comma-separated list is rejected with 400 too. detail takes only slim or full in lower case; any other value is rejected with 400 and the message detail must be 'slim' or 'full'.
  • The two listings handle a large limit differently. List transactions holds a limit above 200 to 200 and shows 200 in pagination.limit. List the records of a transaction rejects it with 400 and the message max cannot exceed 200. Both default to 20 and accept max as another name for limit. A limit of 0 or a negative offset is rejected with 400.
  • Sorting and searching are ignored. List transactions ignores search, q, sort, order and parameters it does not know, and always returns numbers in ascending order. List the records of a transaction ignores sort and order and always returns records newest first. To find one number, send it as the transaction_no query parameter.
  • Past the last row, a listing returns no rows. Both listings then return pagination.has_previous set to false, even though earlier rows exist, and pagination.current_page equal to pagination.total_pages. Stop when pagination.has_next is false.
  • No response has an ETag. Every response has Cache-Control: no-cache, no-store.
