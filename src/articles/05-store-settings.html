The store settings endpoints let your software read and change how a store is set up: its details, logo and email settings, stock and pricing rules, customer portal, price display, product listings, search, SEO, shipping defaults and animation effects. All fifty-four endpoints are available in every WebCommander SDK.

The settings are split into nine areas, and each has its own reference: Site settings, Ecommerce settings, Customer portal, Price display settings, Product listing, Search settings, SEO configuration, Shipping settings and Animation effects.

Common tasks

You want to Use
Change the store's business name, address, contact email or ABN Update a settings section in Site settings, with section set to store_details
Set a minimum purchase amount or payment terms Update a settings section in Ecommerce settings, with section set to pricing
Open or close customer registration, or turn customer login on or off Update a customer portal section, with section set to registration or login, and enabled set to true or false
Show each line item's price with tax included Update a settings section in Price display settings, with section set to order_item, turning on price_including_tax
Change how many products a listing page shows, or how it is sorted Update product listing settings
Make a search for one word also find another, such as phone and mobile Update a search settings section, with section set to synonyms, then Get the reindex status to see when the reindex has finished
Send visitors from an old URL to a new one Create a redirect. It returns the redirect's id, which the other redirect calls take as redirect_id
Add a site verification file or ads.txt Upload a document root file
Choose the store's default shipping profile Update shipping settings, with the shipping profile's id in default_shipping_profile
See which values a setting accepts before you change it Add field_metadata=true when you read an area or one of its sections, such as with Get ecommerce settings. The response then also describes each field

All endpoints

Site settings

Read and change your store's details, logo, favicon, brand colours, date and time formats, units of measure, CAPTCHA, and domain and email settings. See the Site settings reference.

{{endpoints:site_settings}}

Ecommerce settings

Read and change where the continue shopping link leads, how the store handles stock, minimum purchase amounts and payment terms, product restriction, the status each admin order list opens on, and whether the store uses more than one stock location. See the Ecommerce settings reference.

{{endpoints:ecommerce_settings}}

Customer portal

Turn the customer portal on or off, change its registration, login and single sign-on settings, and read its profile page and registration form. See the Customer portal reference.

{{endpoints:customer_portal}}

Price display settings

Read and change how prices, tax, discounts and order totals show in the shopping cart, at checkout and on the order success page. See the Price display settings reference.

{{endpoints:price_display_settings}}

Product listing

Read and change what your store's product listings show for each product, and how they page and sort. See the Product listing reference.

{{endpoints:product_listing}}

Search settings

Read and change the content your store's search covers, the product fields it matches and its synonym groups, and check the status of a search reindex. See the Search settings reference.

{{endpoints:search_settings}}

SEO configuration

Read and change your store's SEO title and description templates, the custom code added to every page and the URL settings, and manage redirects and document root files, such as a site verification file or ads.txt. See the SEO configuration reference.

{{endpoints:seo_configuration}}

Shipping settings

Read and change your store's default shipping, delivery and shipping tax profiles, whether the default tax applies to shipping and delivery, and its shipping class settings. See the Shipping settings reference.

{{endpoints:shipping_settings}}

Animation effects

Read and change the loader your store shows while a page loads, its widget and page transitions, image lazy loading and the checkout page skeleton. See the Animation effects reference.

{{endpoints:animation_effects}}

Good to know

A replace call resets the fields you leave out

Search settings and SEO configuration have replace calls as well as update calls. A replace call resets every field you leave out of a section you send: replacing the SEO url_settings section with only regenerate_url_on_item_update turns a stored true in auto_redirect_on_url_change back to false. Replace search settings also resets any section you leave out, including synonyms, and a change to synonyms starts a search reindex that cannot be undone. To change a few fields, use an update call: it changes only the fields you send.

After a 400 error, create a new client

A write rejected with 400 can affect the next call made with the same SDK client. In Customer portal and Animation effects, the next write can be rejected even when it is valid. In Ecommerce settings, after a section update is rejected, the next read can return 200 with a different section from the one you asked for. After a 400, create a new client before you make another call.

Put each field inside its section

Most areas group their fields into sections, such as pricing or brand_kit. When you update a whole area, wrap the sections in the area's name, for example {"ecommerce_settings": {"pricing": {"enable_payment_terms": true}}}. When you update a single section, wrap the fields in the section's own name instead. Product listing has no calls for a single section, and Shipping settings has no sections, so make every change there with Update product listing settings or Update shipping settings. In Update site settings, a field sent outside its section is ignored and the call still returns 200, so check the response to confirm the change.

  • Site settings calls are slow. A read of all site settings takes about fifteen seconds, and a write takes thirteen to fifteen seconds. Allow for that in your client's timeout.
  • Secret site settings read back as ***. They are the SMTP password, the SendGrid API key, the CAPTCHA private keys and the site lock code. Send a new value to change one, and leave it out to keep it. Send only the fields you change, not a copy of a read.
  • Some areas limit how fast you can write. Customer portal rejects the eleventh write within about 3.25 seconds with 429, and Animation effects rejects the eleventh within about 0.8 seconds. SEO configuration limits writes in each ten-second window. Wait for the time in the Retry-After header before you write again: a retry sent sooner counts as another write.
  • In Price display settings, scopes follow enabled unless customize is true. While a setting's customize is false, turning enabled on sets every entry in its scopes to true, whatever scopes you send. To choose the shopping cart, checkout and order success page one by one, send customize: true with your scopes.
  • Turning off shipping classes also turns off enable_flat_view_class. When you set enable_shipping_class to false, enable_flat_view_class becomes false too. While shipping classes are off, a write of enable_flat_view_class: true returns 200 but the value stays false. Turning shipping classes back on does not restore it, so send enable_flat_view_class: true as well, and check the value in the response.
