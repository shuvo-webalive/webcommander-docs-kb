WebCommander gives you access to a store's admin data through the v4 REST API. Seven SDKs wrap that API with the same set of calls in every language: Python, JavaScript, PHP, Java, .NET, Dart and Go.

This article is an overview. The full API and SDK reference, with every request, response and code sample, is in the WebCommander developer documentation.

Open the developer documentation

What you can do with the API

Area What you can do
Customers List, read, create, update and delete customers, export and import them, manage addresses, passwords and store credit.
Page settings Read and update the category, product, search result, shopping cart and checkout page settings.
Store settings Read and update site, e-commerce, customer portal, price display, product listing, search, SEO, shipping and animation settings.
Tax Manage tax codes, rules, zones, profiles, custom profiles, country taxes and the store's tax settings.
Shipping Manage shipping methods and shipping classes.
Inventory and orders Manage inventory locations and order flags.
Domain aliases List, add and remove the extra hostnames a store answers on.

What the SDKs handle for you

  • Authentication. The client exchanges your store's credentials for an access token, caches it and renews it when it expires.
  • One client for everything. Each area above is a property on the client, and each endpoint is a method on it.
  • Clear failures. An error status is reported as a failure, and so is a response that says "isSuccess": false.
  • Retries. A call that never reached the store is retried automatically.
