The Gift cards API lets your software list a store's gift cards, newest first, and filter them by code, email address or active state. Use it to find a customer's cards and their balances before you apply one to an order preview. The one endpoint is available in all seven WebCommander SDKs, at /api/v4/admin/gift_cards.

Common tasks

You want to Use
List the newest gift cards List gift cards with limit up to 20. For more, send page or offset while pagination.has_next is true
Find the gift cards of one customer List gift cards with email set to the customer's whole email address, such as email=jane.doe@example.com. The match ignores letter case, and a part of an address matches nothing
Look up one gift card by its code List gift cards with code set to the whole code. A part of a code matches nothing
Keep only the cards a customer can still use List gift cards with is_active=true, then check each card's is_paid, balance and available_to. is_active takes true, false, 1 or 0
Pay for a previewed order with a card Read the card's code from the listing, then call Apply a gift card to a preview

All endpoints

This one endpoint lists gift cards, at the path /api/v4/admin/gift_cards.

{{endpoints:gift_cards}}

Good to know

  • A listing returns at most 20 gift cards per call. A larger limit is capped at 20, and pagination.limit shows 20. limit=0 is rejected with 400 and the reason invalid_pagination.
  • The listing accepts only six parameters. limit, offset, page, code, email and is_active. Any other name, such as is_paid, balance, customer_id or sort, is rejected with 400 and the reason unknown_parameter. An is_active value other than the four is rejected with invalid_boolean.
  • A card pays only for the customer whose email address it holds. Each card's email must equal the email of the customer record you preview an order for.
  • This API only lists gift cards. There is no endpoint to create or change one.
