The Inventory locations and Order flags APIs let your software work with a store's inventory locations and order flags. You can list, create, replace and delete locations, activate or deactivate them, choose the default location and see the products each one holds. You can also list, create, read, replace and delete the store's order flags. All seventeen endpoints are available in all seven WebCommander SDKs.

Good to know

A replace resets the fields you leave out. Replacing a location or an order flag does not merge your changes with what is already there. On a location, name is required, an address you leave out becomes null and an active you leave out becomes true; default keeps its current value if you leave it out. Sending "default": false for the default location is rejected with 409; make another location the default instead. On an order flag, name and color are required every time, and a description you leave out becomes null. Always send every field you want to keep.

Order flag fields go inside order_flag, location fields do not. When you create or replace an order flag, put its fields inside order_flag, for example {"order_flag": {"name": "Awaiting Stock", "color": "#5A7BD4"}}. Without order_flag, the call is rejected with 400 and the message order_flag missing. Inventory locations are the opposite: send name, address, active and default at the top level of the body. Any other field, including an inventory_location wrapper, is rejected with 400. The older names is_active and is_default are still accepted.

  • New locations start active. A new location has active set to true unless you send false.
  • At most one location is the default, and you cannot delete the default location. Setting a new default, or creating a location with "default": true, means the location that was the default stops being the default. To delete the default location, first make another location the default, or the delete is rejected with 409.
  • Lists return 20 items at a time unless you send limit. For locations and the products at a location, limit can be up to 100; to get more, send a higher offset while pagination.has_next is true. Order flags return at most 20 per call, whatever limit you send; get more with the next page or a higher offset.
  • No call changes stock. The stock listing is read-only, and a method a location path does not support is rejected with 405. To change a location, use Replace an inventory location, or Activate or deactivate an inventory location to change only active.
  • A check does not tell you whether a location or order flag exists. Check an inventory location and Check an order flag return 200 even when nothing has the id you send. To find out whether it exists, use Retrieve an inventory location with the location's id as inventory_location_id, or Retrieve an order flag with the flag's id as order_flag_id. Both return 404 when nothing has that id.
