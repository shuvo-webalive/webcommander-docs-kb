The Inventory locations and Order flags APIs let your software work with a store's inventory locations and order flags. You can list, create, replace and delete locations, activate or deactivate them, choose the default location and see the products each one holds. You can also list, create, read, replace and delete the store's order flags. All seventeen endpoints are available in all seven WebCommander SDKs.

Good to know

A replace resets every field you leave out

Replacing a location or an order flag does not merge your changes with what is already there. On a location, a field you leave out is reset: address becomes "", and is_active and is_default become false. If you replace the default location without is_default, the store has no default location until you set one again with Set the default inventory location. On an order flag, name and color are required every time, and a description you leave out becomes null. Always send every field you want to keep.

Order flag fields go inside order_flag, location fields do not

When you create or replace an order flag, put its fields inside order_flag, for example {"order_flag": {"name": "Awaiting Stock", "color": "#5A7BD4"}}. Without order_flag, the call is rejected with 400 and the message order_flag missing. Inventory locations are the opposite: send name, address, is_active and is_default at the top level of the body. A create with the fields inside inventory_location is rejected with 400 and the message name is required.

  • New locations start inactive. A new location has is_active set to false unless you send true.
  • At most one location is the default, and you cannot delete the default location. Setting a new default, or creating a location with "is_default": true, means the location that was the default stops being the default. To delete the default location, first make another location the default, or the delete is rejected with 409.
  • Lists return up to 20 items at a time. This applies to locations, to the products at a location and to order flags, and a larger limit does not change it. To get more, send the next page or a higher offset while pagination.has_next is true.
  • A 200 does not prove a location change was saved, and no call changes stock. If you use a method the location paths do not support, such as PATCH on a location or any write to a location's stock, the store returns 200 with "isSuccess": false and saves nothing. To change a location, use Replace an inventory location, or Activate or deactivate an inventory location to change only is_active. The stock listing is read-only.
  • A check does not tell you whether a location or order flag exists. Check an inventory location and Check an order flag return 200 even when nothing has the id you send. To find out whether it exists, use Retrieve an inventory location with the location's id as inventory_location_id, or Retrieve an order flag with the flag's id as order_flag_id. Both return 404 when nothing has that id.
