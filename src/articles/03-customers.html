The Customers API lets your software work with a store's customers: find, create, update and delete them, export them to a spreadsheet, import them from a file, and manage their addresses, passwords and store credit. All fifteen endpoints are available in every WebCommander SDK.

Good to know

Use customer_id, not internal_id

Every customer has two ids: customer_id and internal_id. Endpoints take customer_id. If you send an internal_id by mistake, you can get a different customer back instead of an error, so check that the customer you get back is the one you asked for.

New customers cannot sign in until they are active

A customer created without status: "active" is created as awaiting_verification and has no usable login, even with a password. To create a customer who can sign in straight away, send status: "active" with a password.

  • Lists return up to 20 customers at a time. To get more, send the next page number or a higher offset.
  • An export always contains every customer. Its options choose which columns appear, not which customers. Importing an export rewrites every customer in the store, so build import files from only the customers you want to change.
  • A bulk password reset queues a reset email for each customer. The call returns before any email is sent. Check queued and skipped in the result: an id that matches no customer is listed in skipped with a reason.
  • An import can partly succeed. It can return 201 even when some rows failed, so check failed and errors in the result.
