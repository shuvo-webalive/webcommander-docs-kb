The Tax API lets your software manage a store's tax setup. You can list, create, update and delete tax codes, tax rules, tax zones, tax profiles, custom tax profiles and country taxes, and change the store's tax settings. All forty-one endpoints are available in all seven WebCommander SDKs.

Tax has seven parts, and each has its own reference: Tax codes, Tax rules, Tax zones, Tax profiles, Custom tax profiles, Country taxes and Tax settings.

Open the Tax codes reference

Common tasks

You want to Use
Change the store's tax message or whether prices show with tax Update tax settings (PUT) or Patch tax settings (PATCH), with only the fields you change, such as tax_message or is_price_shown_with_tax, inside tax_settings. Both change only the fields you send
Add a new tax rate Create a tax code with a name and a rate
Change the rate of a tax code Retrieve a tax code, passing the tax code's id as tax_code_id, then Update a tax code with the new rate and the tax code's current priority and resolver_type
Set the tax rate for a country Create a country tax with the country's code, such as NZ, in country_code. To change the rate later, use Update a country tax with a new tax_rate, passing the country tax's id as country_tax_id
Group countries, states and post codes into a tax zone Create a tax zone with a name. Send each country in countries as {"id": 12}, where 12 is the country's id from the countries of a zone in List tax zones. Send each state in states the same way, and the post codes in post_code as a flat list
Make a tax profile the store's default Update a tax profile with default: true, passing the tax profile's id as tax_profile_id

All endpoints

Tax codes

Create, update and delete the store's tax codes, each with a name, a label and a rate. See the Tax codes overview.

{{endpoints:tax_codes}}

Tax rules

Create and delete tax rules, change their name and description, and read the tax code and tax zones on each rule. See the Tax rules overview.

{{endpoints:tax_rules}}

Tax zones

Create, update and delete tax zones, each a named set of countries, states and post codes. See the Tax zones overview.

{{endpoints:tax_zones}}

Tax profiles

Create, update and delete tax profiles, read the tax rules each profile uses in tax_rules, and choose which profile is the store's default. See the Tax profiles overview.

{{endpoints:tax_profiles}}

Custom tax profiles

Create, replace and delete custom tax profiles, which are separate from tax profiles, and read the rate rules each one holds. See the Custom tax profiles overview.

{{endpoints:tax_custom_profiles}}

Country taxes

Create, update and delete country taxes, each with its own tax rate, and read their state rules. See the Country taxes overview.

{{endpoints:tax_country_taxes}}

Tax settings

Read and change the store's tax settings, such as the tax region, whether prices show with tax and the tax message. See the Tax settings overview.

{{endpoints:tax_settings}}

Good to know

Some updates reset the fields you leave out. Updates to tax profiles, tax rules, country taxes and tax settings change only the fields you send. Three others do not. An update to a tax code sets priority to 0 and resolver_type to flat if you leave them out. Replacing a custom tax profile sets description to null if you leave it out. An update to a tax zone empties countries, states and post_code if you leave them out, and sets use_radius to false if you leave it out. Custom tax profile and tax zone updates also need name every time. For these three, send the current values of every field you want to keep.

A failed request can make the next request fail too. When a tax request is rejected, the next request on the same connection can fail in the same way, even if it is correct. After a 404, the next request for one record can return 404 for a record that exists, even in another part of Tax, and a delete returns that 404 and deletes nothing. After a list is rejected for its limit or offset, the next list returns the same 400. The request after that works normally. If a call fails straight after another failed call, send it again, and read the record back to confirm a change or a delete.

Put each write inside the right key. For every create and update, send the fields inside one key named after the record: tax_code, tax_rule, tax_zone, tax_profile, custom_profile or country_tax, for example {"tax_code": {"name": "LUXURY", "rate": 15.0}}. Tax settings use tax_settings, the same key the read returns: tax is accepted too, and a body wrapped in settings is rejected with 400. A body without the right key is rejected with 400.

  • Lists return up to 20 or 100 records at a time. Tax codes, tax rules, custom tax profiles and country taxes return up to 100 records. Tax profiles and tax zones return up to 20. A larger limit returns the maximum, and pagination.limit shows it. To get more, raise offset by the number of records each page returned until you reach pagination.total. q does not filter any tax list.
  • The Check endpoints do not tell you whether a record exists. They return 200 even when no record has the id you pass as tax_code_id, tax_rule_id, tax_zone_id or tax_profile_id. Use the matching Retrieve endpoint instead, which returns 404 when no record has that id.
  • You cannot set a tax rule's tax code or zones. A create or update accepts code, zones, decimal_point and rounding_type but does not store them. A rule you create has code: {} and zones: [].
  • Only one tax profile is the default. At most one tax profile is the default. To change it, send default: true in Update a tax profile for the new default. Sending default: false leaves the flag where it is.
  • Send a tax zone's post codes as a flat list. Send ["2000", "3000"] in post_code. The zone returns them in the same flat form, and sending a nested list fails with 500.
  • Write the custom tax profile as custom_tax_profile_id and the tax region as an object. The read returns the profile as custom_tax_profile, but a write that contains custom_tax_profile or calculated_by is rejected with 400 and the code unknown_field. Send the custom tax profile's id as custom_tax_profile_id. Send tax_region as an object such as {"country_code": "AU"}: {"country_tax_id": 1} is accepted but leaves tax_region as null, and a bare id is rejected with 400.
