The Shipping rates API lets your software work with a store's shipping rates. A shipping rate is the price a shipping rule applies, and its method decides how the price is worked out: a flat amount, free shipping, or an amount by the order's price, quantity, weight or variation. You can list, count, create, retrieve, replace, update and delete rates. All ten endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get every rate, or only some List shipping rates, page by page. Each call returns up to 20 rates under shipping_rates, newest first, or up to the limit you send, from 1 to 100. Send search=flat to get the rates whose name contains that text, method=flat_rate to get one kind of rate, and handling_cost=with_handling to get the rates that have a handling cost. Count shipping rates takes the same filters and returns the number of matches as total
Add a flat rate Create a shipping rate with {"shipping_rate": {"name": "Flat 10", "method": "flat_rate", "shipping_cost": {"amount": 10, "type": "fixed"}}}. It returns 201 and the new rate, with its id. Pass that id as shipping_rate_id to retrieve, change or delete the rate
Add a rate that depends on weight Create a shipping rate with method set to ship_by_weight and a conditions list. Each row has from, to, packet_weight, a shipping_cost and a handling_cost. The same works for ship_by_price, ship_by_quantity and ship_by_variation, with the row fields that method takes
Put a new rate on a shipping rule Create a shipping rate with shipping_rule_id set to the id of a shipping rule that has no rate yet
Change one field of a rate Update a shipping rate with the rate's id as shipping_rate_id and only the field to change inside shipping_rate, such as {"shipping_rate": {"shipping_cost": {"amount": 12, "type": "fixed"}}}. Every field you leave out keeps its value. To replace the whole rate, use Replace a shipping rate
Remove a rate Delete a shipping rate with the rate's id as shipping_rate_id. It returns 204 with no body. A rate that a shipping rule uses is rejected with 409

These ten endpoints list, count, create, retrieve, replace, update and delete shipping rates, at paths that start with /api/v4/admin/shipping_rates.

Good to know

A rate that a shipping rule uses cannot be deleted. Delete a shipping rate on it is rejected with 409, the code in_use and the id of the rule. The shipping_rules list on the rate shows which rules use it. Delete those rules, or take the rate off them, first.

Send the fields inside shipping_rate. Create, replace and update take {"shipping_rate": {...}}. A body without the wrapper is rejected with 400, and so is a field the rate does not have or an id in the body. Responses return the rate inside shipping_rate.

  • method decides which fields a rate takes. It is required, and it is flat_rate, free_shipping, ship_by_price, ship_by_quantity, ship_by_weight, ship_by_variation or shipping_variant. A flat_rate needs shipping_cost and takes handling_cost and additional_rule. The four ship_by_... methods take their costs per row in conditions, and a shipping_cost at the top level of the rate is rejected with 400. free_shipping and shipping_variant need no cost. A cost is {"amount": 10, "type": "fixed"}, and type is fixed or percent.
  • Rows in conditions must not overlap. A price or quantity row has from, to, shipping_cost and handling_cost. A weight row also has packet_weight. A variation row has variation_combination, a list of {"id": ...} with a variation's id, instead of from and to. Rows that overlap are rejected with 400 and the code overlapping_range.
  • free_shipping always saves calculate_for_entire_order as false. The store ignores a true you send. price_entered_with_tax keeps your value.
  • PUT replaces a rate, and PATCH changes only the fields you send. Replace a shipping rate needs name, method, calculate_for_entire_order and price_entered_with_tax, the costs the method uses, handling_cost and additional_rule, and names each missing field in the 400 response with the code required. handling_cost and additional_rule take null. An update with an empty shipping_rate object returns 200 and changes nothing.
  • Rate names are unique, in any letter case. A name that another rate has is rejected with 409 and the code duplicate. Send suggest_name as true on a create to get the next free name, such as Flat 10(1), instead. A shipping_rule_id that names a rule that already has a rate is rejected with 409 and the code in_use.
  • An extra cost for further items is additional_rule. It is {"enabled": true, "for_each_additional": 2, "additional_cost": 1.5}. When enabled is true, for_each_additional must be 1 or more and additional_cost 0 or more.
  • Older rates can return a method other than the seven names. For example FLAT_RATE or [sbq, sbq], with shipping_cost set to null. Treat any other value as unknown, and send only the seven names on a write.
  • You can file a rate under a transaction number. Send transaction_no inside shipping_rate, or the X-Transaction-No header on a create. When you send both, the header wins.
  • A listing returns 20 rates per call unless you send limit. limit takes 1 to 100: 0, a value above 100 and a value that is not a number, such as all, are rejected with 400. To get more, send a higher offset while pagination.has_next is true. sort takes id, name, method, created_at, updated_at or transaction_no, and order takes asc or desc.
