Every call to the WebCommander API needs an access token. With the new sign-in, you create an API application in the WebCommander admin and use its client ID and client secret to get the token. The SDKs get the token, keep it and renew it for you. This article explains the credentials, how to set up an SDK, and how to request a token yourself.

See Authentication (New) in the developer documentation

If your store still signs in with a redirect URI and an auth string, read Authentication (Legacy) instead.

Only the token request changes. Every API call still goes to your WebCommander store's base URL, with the same paths, parameters and responses as before. Your Hykmah base URL is used for nothing but getting and renewing the access token.

Which address each request uses

Your integration works with two addresses. Keep them apart:

  • Base URL is your WebCommander store's own address, for example https://your-store.example.com. It is the same address you use today, and every API call goes to it: customers, orders, products, settings and every other endpoint.
  • Hykmah base URL is the address that issues access tokens. Your integration sends exactly one kind of request there: getting or renewing a token. It never receives an API call.

Example

Say your store is at https://your-store.example.com. With the new sign-in, your integration makes these requests:

StepRequestSent to
1. Get a tokenPOST /api/v1/oauth/token with the client ID and client secret as form dataYour Hykmah base URL
2. Call the APIGET https://your-store.example.com/api/v4/admin/customers with Authorization: Bearer ACCESS_TOKENYour store's base URL, as before
3. More callsOrders, products, settings and every other endpoint, with the same tokenYour store's base URL, as before
4. Renew the tokenPOST /api/v1/oauth/token with grant_type set to refresh_tokenYour Hykmah base URL

With an SDK you never write these requests yourself. Give the client your store's base URL and your Hykmah base URL once; it sends the token request to the Hykmah base URL and every API call to your store's base URL.

Common mistakes

  • Sending API calls to the Hykmah base URL. It only issues tokens; send every API call to your store's base URL.
  • Replacing the base URL with the Hykmah base URL. Keep the base URL set to your store's address. The Hykmah base URL is an additional setting, not a replacement.
  • Requesting the token from the store. The store's /api/v4/oauth2/token is the legacy token request. With the new sign-in, request the token from your Hykmah base URL.
  • Sending the token request as JSON. The Hykmah token request accepts form data only; JSON is rejected.

Your credentials

Credential What it is
Base URL Your store's address, including https://. Every API call goes here.
Hykmah base URL The address that issues access tokens. Only the token request goes here.
Client ID Identifies your API application.
Client secret The secret paired with the client ID.

You get the client ID and client secret when you create an API application in the WebCommander admin. There is no redirect URI and no auth string to configure. The steps are in the Create API Application guide.

Keep your client secret private. It gives access to your store's data through the API. Keep it in an environment variable or a secrets manager, never in source code or a shared document.

Set up an SDK

Register your credentials once, when your app starts. The only new setting is the Hykmah base URL. Its name depends on the language:

Language Hykmah base URL option
Python auth_base_url
JavaScript, PHP, Java, Dart authBaseUrl
.NET authBaseUrl argument, AuthBaseUrl property
Go AuthBaseURL

The developer documentation has a complete registration sample for each language and for cURL. Use SDK version 4.0.2 or later.

What the SDKs handle

  • Getting the token. On the first call, the SDK sends your client ID and client secret to your Hykmah base URL and gets an access token.
  • Caching and renewal. The SDK keeps the token and renews it before it expires, using the refresh token.
  • An expired token. If a call returns 401 because the token has expired, the SDK renews the token once and sends the call again.
  • A real refusal. Any other 401 is returned to you and not retried, so a write is never sent twice.

Requesting a token yourself

With cURL or any HTTP client, send a POST request to /api/v1/oauth/token on your Hykmah base URL. The body must be form data with the header Content-Type: application/x-www-form-urlencoded. A JSON body is rejected with a 400 error.

Form field Value
grant_type client_credentials
client_id Your client ID.
client_secret Your client secret.

A successful request returns 200 with these fields:

Field Meaning
access_token The token to send with each call.
token_type Always Bearer.
expires_in Seconds until the token expires. Currently 3600.
refresh_token Exchanged for a new access token when this one expires.
scope The access the token grants.

Send the access token in an Authorization: Bearer header on every API call. API calls go to your store's base URL, not to your Hykmah base URL.

To renew a token, send a form to the same address with grant_type set to refresh_token, your refresh_token, your client ID and your client secret. The response has the same fields.

Using both sign-ins in one app

One app can call a store that uses the new sign-in and a store that still uses the legacy one. Register one configuration for each and give each a client name. The configuration with a Hykmah base URL signs in the new way. The one without it signs in with its redirect URI and auth string. Build a client by name to choose the store. With no name, you get the first one registered. The developer documentation shows this in every language.

Try it in the documentation

Open Get an access token (New), click Try it, enter your client ID and client secret, and send the request. Copy the access token from the response. Then open any endpoint, set the store to your store's host name, paste the token into Authorization and send. These calls run against your real store, so use test data.
