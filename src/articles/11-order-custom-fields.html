The Order custom fields API lets your software read the custom fields a store's orders can have, such as a gift message or a preferred delivery date. You can list and count the fields, retrieve one field with its choices, hover text, placeholder and default value, and check whether a timeslot on a date is available under an order limit. You cannot create, change or delete order custom fields through the API. All four endpoints are available in all seven WebCommander SDKs.

All endpoints

These four endpoints list, count and retrieve the store's order custom fields and check a timeslot against an order limit, at paths that start with /api/v4/admin/order_custom_fields.

{{endpoints:order_custom_fields}}

Good to know

Validating a timeslot stores nothing, even though it returns 201. Validate a timeslot does not reserve the timeslot or change the order custom field: the field's last_updated_on and the number of order custom fields stay the same, and the same check sent again returns the same result. The status is 201 whether the timeslot is available or not, so read valid in the response: true with the message Timeslot available, or false with Timeslot fully booked. An order_limit of 0 returns valid: false, and a negative order_limit, or none, returns valid: true.

Send the timeslot keys at the top level of the body. Put selected_date, weekday_id, start_hour, end_hour and order_limit straight into the body, as in {"selected_date": "25/10/2026", "weekday_id": 1, "start_hour": 9, "end_hour": 12, "order_limit": 10}. A body wrapped in a key, such as {"validate_timeslot": {...}} or {"order_custom_field": {...}}, is read as a body without selected_date. The store rejects it with 400 and the message selected_date: is required, in dd/MM/yyyy form, e.g. 25/07/2026. selected_date is required and must be a real date written dd/MM/yyyy, such as 25/10/2026. 31/02/2026, 2026-10-25 and 5/1/2026 are rejected with 400. When order_limit is above 0, also send start_hour and end_hour, each a whole number from 0 to 23, or the call is rejected with 400.

After a rejected query parameter, your next call can be rejected too. When a query parameter is rejected with 400, your next call on the same client returns the same 400 if its endpoint reads that parameter, even when that call's own parameters are valid. List order custom fields reads all seven of its parameters: limit, offset, page, sort, dir, filterBy and field_metadata. Retrieve an order custom field reads field_metadata, and Count order custom fields reads filterBy. If a call with valid parameters returns that 400, send it again: the second try runs normally, and so does every call on a new client. A rejected timeslot body does not affect the next call.

  • You can read order custom fields, but not create, change or delete them. POST on /api/v4/admin/order_custom_fields, and PUT, PATCH and DELETE on /api/v4/admin/order_custom_fields/{order_custom_field_id}, are rejected with 405 method_not_allowed and the message HTTP method not allowed for this endpoint. The listing's group_meta shows writable: false. OPTIONS lists HEAD in its Allow header, but HEAD returns 404 on the listing and on an order custom field's path, and 405 on /count. Use GET instead.
  • A listing returns at most 20 fields per call. A larger limit is capped at 20, and pagination.limit shows 20. To get every field, raise offset by the number of fields each page returned, pagination.count, until you reach pagination.total. filterBy limits both the listing and the count to one field type. No parameter searches the fields: the listing ignores q, search, name, label and is_active. To find one field, page through the listing and look for its name or label.
  • sort takes its own names for five keys, not the names the response uses. Send sort=type to sort by field_type, sort=orderNo for order_no, sort=isActive for is_active, sort=created for created_on and sort=updated for last_updated_on. sort=field_type and the other four response names are rejected with 400, and so is a leading -: set dir to asc or desc instead. sort=id, sort=label and sort=name sort by the order custom field's id, label and name.
