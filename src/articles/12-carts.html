The Carts API lets your software build a customer's cart and turn it into an order. You can add products to a cart, read the cart with its items, totals and shipping taxes, change an item's quantity, remove one item or empty the cart, get the session_id to use for a cart, and create an order from the cart's items. All seven endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Start a cart for a customer and add a product to it Add a product to a cart with {"product_id": 101, "quantity": 1, "customer_id": 45, "session_id": "cart-7f3a9c2e1b"}: the product's id as product_id, the customer's internal_id as customer_id, and a session_id you choose to name the cart. It returns the whole cart under cart
Show what is in a cart, with its totals and shipping taxes Retrieve a cart with the cart's session_id. It returns the cart under cart, with its items, its totals, and its shipping cost and taxes in shipping
Change how many of a product the cart holds Update a cart item with the cart's session_id and {"cart_item_id": 42, "quantity": 2}: the cart item's id, from items[].id in a cart response, as cart_item_id, and the new quantity. It returns the updated cart. The store numbers cart items across all carts, so do not count from 1
Take one product out of the cart, or empty the cart Remove an item from a cart with the cart's session_id and the cart item's id as cart_item_id, or Empty a cart to remove every item. Both return 204 with no body
Set the cart's shipping taxes for the country you ship to Add a product to a cart or Update a cart item with a shipping_address. Its country_code, such as AU, decides shipping.shipping_tax and shipping.handling_tax
Turn the cart into an order Create an order from a cart with the cart's session_id and {"customer_id": 123}: the customer's customer_id, not the customer's internal_id that you sent when you added products. It returns the new order under order and empties the cart
Give the order a shipping and billing address other than the customer's saved ones Update a cart item with a shipping_address and a billing_address, as well as the required cart_item_id and quantity. Then call Create an order from a cart with the same JSESSIONID cookie as that update

All endpoints

Six of the seven endpoints have paths that start with /api/v4/carts and use the same access token as every other endpoint, and Create an order from a cart uses /api/v4/admin/orders/carts/{session_id}.

Good to know

Adding a product and creating an order take different numbers for the same customer. Add a product to a cart takes the customer's internal_id in its customer_id field, and rejects the customer's customer_id with 400 and the message No Customer Found. Create an order from a cart takes the customer's customer_id, and a body without customer_id is rejected with 400 and the same message, No Customer Found; the cart stays as it was. Create a customer returns both values.

Only the response to adding a product shows the customer. Its cart.customer_id is the customer's internal_id you sent. Retrieve a cart and Update a cart item return cart.customer_id as null, even when your client sends back the JSESSIONID cookie the store set. A cart never holds the customer's customer_id, so keep it yourself: Create an order from a cart needs it.

You name each cart with a session_id you choose. Send it in the body each time you add a product, and pass the same value as the session_id path parameter in every other cart call. If you add a product without it, the store names the cart with your HTTP session's 32-character JSESSIONID cookie value, and only cart.session_id in the response tells you that name. Resolve a cart session returns the value to use as the cart's session_id, in a field named sessionId. Send {} to get back the session_id from the path, or send "sessionId": null to get your HTTP session's JSESSIONID: the cookie your client sends, or a new value when it sends none. It changes no cart: it does not move or merge carts, even when the sessionId you send names another cart.

  • A cart exists only while it has items. Reading a cart with no items returns 400 with the message Your shopping cart is empty, not 404. That happens after you empty the cart, remove its last item or turn it into an order, and for a session_id you never used. Emptying a cart that is already empty returns the same 400.
  • Adding a product that is already in the cart raises that item's quantity. The cart gets no second entry for the product: the cart item's id stays the same, and its quantity goes up by the quantity you send. To set an exact quantity, use Update a cart item.
  • The shipping address sets the cart's shipping taxes, but no cart response returns an address. The shipping_address.country_code you send when you add a product or update an item decides shipping.shipping_tax and shipping.handling_tax, and every later read of the cart shows the result. Without a shipping address, both are 0.0. The store does not check any address field, and accepts {}. Write the first address line as address_line1, without the underscore before the 1 that an order's address_line_1 has.
  • An order gets the customer's saved addresses by default. When you send shipping_address and billing_address to Update a cart item and then call Create an order from a cart with the same JSESSIONID cookie, the order gets those two addresses instead. Addresses you send when you add a product never reach the order. The order's shipping_tax follows the order's addresses, so it can differ from the cart's shipping.shipping_tax. No cart call changes the customer's saved addresses.
  • A 200 does not always mean the call worked. The store does not handle GET on /carts, POST on /carts/{session_id}, or GET and PATCH on /carts/{session_id}/cart_items/{cart_item_id}: each returns 200 with {"isSuccess": false, "message": "Invalid API Request"}. Add products with POST on /carts, and change an item's quantity with PATCH on /carts/{session_id}.
  • Update a cart item returns 500 without quantity or with customer_id. Always send quantity: without it, the message is Cannot invoke method toBigInteger() on null object. Leave customer_id out: with it, the 500 body is not valid JSON, and the new quantity is saved anyway. A quantity of 0 is rejected with 400 and the message f:Minimum required quantity is 1; to take the item out, use Remove an item from a cart.
  • Adding a product that needs options returns 201 without a cart if you send no options. Add a product to a cart returns 201 for such a product, but the body is not valid JSON: it has "status": "incomplete-info" instead of cart.
  • Carts do not reserve stock. Adding a product is rejected with 400 and the message f:<n> quantity of this product is not available when the cart would hold more of the product than its stock, but the limit applies to each cart on its own. The available_stock in a cart item's product is the product's stock, not the item's quantity. A deleted product can still appear in List stock at an inventory location, but adding it is rejected with 400 and the message No product found.
  • A new order is unpaid and stays in your store. It has order_status in_progress, payment_status unpaid, and one order_line_details entry per cart item. When you send "payment_gateway": "PIS" or leave payment_gateway out, the order's payments holds one PIS payment with status awaiting. The response shows transaction_no as null, although the order stores the value you sent. No call in the Carts API deletes the order, and while it is unpaid it does not lower the product's stock.
