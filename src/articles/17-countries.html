The Countries API lets your software read a store's countries and each country's states. You can list countries and states, look up one country by its id, code or name in country_id, look up one of its states the same way in state_id, and get the headers of a list, a country or a state, including its ETag, without the body. Each country has an id, a two-letter code, a name, a state_count, an active flag and a default flag. You can only read countries and states: no call creates, changes or deletes them. All eight endpoints are available in all seven WebCommander SDKs.

Common tasks

You want to Use
Get every country in one call List countries with limit=all. It returns every country under countries, in ascending id order, and pagination.limit is the number of countries returned. Send active=true to get only active countries
Find countries by part of a name or code List countries with search, such as search=zeal. It returns the countries whose name or code contains that text, in any letter case, so gb finds United Kingdom by its code
Look up one country by its code or name Retrieve a country with AU, Australia or the country's id as country_id. It returns the country under country, with its id, code, name, state_count, active and default. It returns 404 and the message Country not found when no country has that country_id
Get the states of a country List the states of a country with the country's code, such as AU, as country_id. It returns the states under states, 20 per call unless you send limit, and the country's id, code and name under country. A country with no states returns an empty states list and a pagination.total of 0
Look up one state Retrieve a state with AU as country_id and VIC, Victoria or the state's id as state_id. It returns the state under state, with its id, code, name, active and default, and the country's id, code and name under country. It returns 404 and the message State not found when that country has no state with that state_id
Find the store's default country and state Get a settings section for the administration section. Its default_country is the store's default country, and its default_state, when one is set, is the default state. That country is the only one with default set to true in List countries
Find out whether the countries list changed without downloading it Check the countries list. It returns 200 with headers only. Its ETag is the one List countries returns when you send no query parameters, so compare it with the ETag you saved

All endpoints

These eight endpoints list and retrieve the store's countries and each country's states, and return the headers of each list, country and state, at paths that start with /api/v4/admin/countries.

{{endpoints:countries}}

Good to know

Send order, not dir, to reverse a listing, and search, not q, to find rows by text. List countries and List the states of a country ignore dir, q, field_metadata and any other parameter they do not know, except page. You get 200 and the same rows as without them. order takes asc or desc, and search matches part of a name or a code. sort takes id, name or code; sort=state_count is rejected with 400.

country_id takes a country's id, code or name, and state_id takes a state's. country_id takes the country's numeric id, its two-letter code or its name. state_id takes the state's id, code or name within that country. Letter case does not matter, surrounding spaces are trimmed, and every form returns the same body and ETag. The SDKs encode the spaces in a name such as New Zealand for you. A state's id is unique across all countries, but Retrieve a state returns 404 and the message State not found when the state in state_id belongs to another country.

Send limit=all to get every row in one call, and offset, not page, to page. limit=all, in any letter case, returns every row from offset on, and pagination.limit is then the number of rows returned, not the word all. Otherwise limit takes 1 to 100 and defaults to 20. To get the next page, send a higher offset while pagination.has_next is true. page is rejected with 400.

  • You can only read countries and states. Every path accepts GET, HEAD and OPTIONS. OPTIONS returns 204 with Allow: GET, HEAD, OPTIONS. POST, PUT and PATCH are rejected with 405, the code method_not_allowed, the message HTTP method not allowed for this endpoint. and the header Allow: GET, HEAD, OPTIONS.
  • Exactly one country has default set to true. It is the default_country in the administration section of the site settings, which you read with Get a settings section. The state named there as default_state, when one is set, is the only state with default set to true.
  • Every read returns an ETag. Each GET response has an ETag and Cache-Control: private, no-cache, and no Last-Modified. Each HEAD returns the same ETag as the matching GET. Send that ETag in If-None-Match on a GET or a HEAD, and while it is still current you get 304 with no body. The SDK functions take no headers, so they never send If-None-Match: you get 304 only from your own HTTP calls.
  • Errors have one shape. The body is an error object with code, message, details and request_id. Each rejected query parameter adds one details entry with its field, code, message and value, and message counts them, such as 1 parameter failed validation. details is empty on a 404 or a 405.
